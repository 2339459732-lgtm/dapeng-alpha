# 自动化交易系统 — 增量 PRD

> 📎 **历史设计（自动化交易 PRD）** — 本文描述的是**当时的需求设计**；**现状以 [`MASTER-PLAN-2026Q4.md`](../00-strategy/MASTER-PLAN-2026Q4.md) 与 [`DATA-DICTIONARY.md`](../30-data/DATA-DICTIONARY.md) 为准**（尤其 M4 的交付边界）。正文保留作演进记录。

## 1. 项目信息

- **Language**: 中文
- **Programming Language**: 后端 Python（FastAPI，沿用现有 `server/` 架构）；前端纯 HTML + 原生 JS（沿用 `static/`，无构建工具）
- **Project Name**: auto_trading
- **原始需求复述**：在现有 DAPENG Alpha 策略选股系统基础上，新增「自动化」能力——
  1. 信号监控 + 邮件自动提醒；
  2. 实盘自动交易；
  3. 双轨策略并行：复用现有面板评分/信号体系 + 新增独立可回测策略引擎（均线组合 / 趋势跟踪等）；
  4. 推送渠道为邮件（QQ 邮箱 SMTP 已配置）。

## 2. 产品定义

### 2.1 Product Goals

1. **信号不遗漏**：用户无需盯盘，系统自动监控股池/自选标的的信号触发，并通过邮件及时送达，同一信号不重复轰炸。
2. **策略可验证**：新增独立策略引擎，所有策略必须先回测、（实盘前）经模拟验证后方可启用，杜绝"裸奔"策略直接下场。
3. **交易有护栏**：实盘自动交易默认关闭，具备金额上限、白名单、熔断、二次确认、全量留痕等安全关卡，用户可随时一键停止。

### 2.2 User Stories

1. 作为一名不能全天盯盘的上班族，我希望当持仓/自选股触发"评分 ≥85"或"MACD 金叉"信号时收到一封邮件提醒，这样我不会错过买点，也不被重复消息打扰。
2. 作为一名策略爱好者，我希望把"MA5/MA20 金叉买入、死叉卖出 + ATR 止损"的参数调成自己习惯的值，先在历史数据上回测看到胜率/回撤，满意后才允许系统用它下单。
3. 作为一名谨慎的个人投资者，我希望实盘下单默认是关的，开启后也能设置单笔不超过 1 万元、单日不超过 3 万元，连续 3 次下单失败系统自动熔断并邮件通知我。
4. 作为一名多标的持有者，我希望只有白名单内的股票才允许自动交易，其他标的一律只发提醒、不下单。
5. 作为一名复盘用户，我希望在面板上看到所有信号历史和订单流水（触发时间、信号、价格、执行结果），方便核对系统行为是否符合预期。

## 3. 技术规范

### 3.1 Requirements Pool

#### P0（本期必做）

| # | 需求 | 说明 |
|---|------|------|
| P0-1 | **信号监控引擎** | 监控范围：26 板块股池 或 用户自选清单（二选一/可组合，配置可选）。触发条件可配：评分阈值（默认 ≥80）、信号类型（动量/突破/MACD金叉/死叉，可多选）、涨跌幅异动（默认 |涨跌幅| ≥ 3%，可配）。扫描频率与现有行情刷新周期对齐。 |
| P0-2 | **去抖与冷却** | 同一"标的+信号类型"组合触发后进入冷却期（默认 30 分钟，可配 5/15/30/60 分钟），冷却期内不重复推送；不同信号类型独立冷却。 |
| P0-3 | **静默时段** | 非交易时段不推送：仅工作日 9:30–11:30、13:00–15:00 触发即时推送；盘前 9:15–9:30 可汇总隔夜信号（可选开关）；休市/节假日完全静默。 |
| P0-4 | **邮件提醒** | 通过已有 QQ 邮箱 SMTP（`QQ_EMAIL_ACCOUNT` / `QQ_EMAIL_PASSWORD`）发送。邮件模板含：标的名称/代码、触发信号、当前价、涨跌幅、触发时间、建议操作提示（措辞为"信号提示"而非投资建议）、面板链接。 |
| P0-5 | **邮件频率上限与重试** | 同一标的每日最多 N 封（默认 5）；全局每小时最多 M 封（默认 20），超限合并为摘要邮件。SMTP 失败指数退避重试最多 3 次，仍失败记录错误并在面板"自动化"卡显示告警。 |
| P0-6 | **策略引擎（可回测）** | 独立模块 `strategy_engine/`，与面板评分体系解耦。内置策略 1：**均线组合**——MA5 上穿 MA20 买入、下穿卖出，ATR(14) 移动止损（参数均可配）。内置策略 2：**趋势跟踪**——突破 N 日新高买入（N 默认 20）、跌破 M 日低点退出（M 默认 10）。所有策略必须先执行回测（复用/修复 `quant_core.py`，依赖补齐 pandas）并展示胜率、年化、最大回撤，回测通过（用户确认结果）后才允许启用。 |
| P0-7 | **风控框架（OrderGateway 抽象 + 安全关卡）** | 定义统一接口 `OrderGateway`（`buy/sell/cancel/query_position/query_account`），本期先实现 **PaperGateway（模拟盘内置实现）**。安全关卡：实盘总开关默认关闭且持久化；单笔金额上限（默认 1 万）、单日累计金额上限（默认 3 万）；持仓白名单（仅白名单标的可自动交易）；熔断器——连续下单失败 3 次自动停止自动交易并邮件告警；所有信号、决策、订单全量落库留痕（SQLite 或 JSON 日志）。 |
| P0-8 | **模拟盘验证闸门** | 策略从"回测通过"到"实盘启用"必须经过模拟盘运行验证（默认至少 5 个交易日或用户手动确认模拟表现），系统强制拦截未经模拟验证的实盘启用请求。即使用户不打算长期用模拟盘，此闸门作为一次性风控准入必须存在。 |
| P0-9 | **面板"自动化"配置卡** | 在现有面板新增卡片：总开关（提醒 / 模拟 / 实盘三档独立）、监控范围与触发条件、冷却时长、静默时段展示、收件邮箱地址、策略选择与参数入口、网关状态指示灯（绿=模拟运行/黄=仅提醒/红=熔断或异常/灰=关闭）。 |
| P0-10 | **信号历史 / 订单流水视图** | 复用现有 `full-overlay-panel` 模式，两个 Tab：信号历史（时间、标的、信号、价格、是否已推送）；订单流水（时间、标的、方向、数量、价格、网关、状态、失败原因）。支持按标的筛选。 |

### 3.2 UI Design Draft

- **入口**：现有面板侧边/顶部新增「自动化」卡片区，风格与现有卡片一致（沿用现有 CSS 变量与配色）。
- **自动化配置卡**：
  - 顶部三档开关行：`[邮件提醒] [模拟交易] [实盘交易]`，实盘开关置灰直到"模拟验证通过"；
  - 网关状态指示灯：●绿（模拟运行中）●黄（仅提醒）●红（熔断/连接异常）●灰（关闭），旁边一行文字说明当前模式；
  - 表单区：监控范围（股池全量 / 自选）、触发条件（评分阈值滑块 + 信号类型多选 + 涨跌幅异动阈值）、冷却时长下拉、收件邮箱输入框、测试邮件按钮；
  - 策略区：策略下拉（均线组合 / 趋势跟踪）、参数表单（MA 周期、ATR 倍数、突破天数）、[运行回测] 按钮、回测结果摘要条（胜率/年化/最大回撤）、[启用] 按钮（回测通过前禁用）。
- **信号历史 / 订单流水**：点击卡片"查看记录"打开 `full-overlay-panel`，顶部两个 Tab，表格列见 P0-10，行内失败状态标红并悬浮显示原因。
- **熔断状态**：触发熔断时配置卡顶部显示红色横幅"自动交易已熔断停止——连续下单失败 3 次"，附 [重置并恢复] 按钮（需用户手动点击）。

### 3.3 合规边界（文档与 UI 措辞约束）

- 所有信号邮件与面板文案使用"信号提示 / 供参考"措辞，**禁止**出现"建议买入/卖出""稳赚""收益保证"等表述；
- 不出现代客理财、代客下单、收益承诺类描述；页脚固定一行："本系统仅为个人量化工具，信号不构成投资建议，据此操作风险自负"。

### 3.4 Open Questions（待确认问题）

1. **券商通道类型**：实盘适配用 QMT（迅投）、PTrade（恒生）还是 easytrader（同花顺客户端）？三者技术栈差异大，直接影响 P1 适配层实现。是否已开通券商量化交易权限？
2. **模拟盘验证层**：用户原始需求未选模拟盘，但本 PRD 将"模拟盘验证通过 + 用户显式开启"设为实盘双重前置（P0-8）。理由：无模拟验证的策略直接实盘，风险不可控且无法区分"策略问题"与"通道问题"。请确认接受该强制闸门，或明确放弃并自担风险（需在实盘开启页展示风险确认勾选）。
3. **信号粒度**：信号监控与策略引擎运行在**日线级**（收盘后扫描 + 次日开盘前邮件）还是**日内分钟级**（依赖现有实时行情，盘中即时触发）？两者对扫描频率、去抖参数、SMTP 频率上限的设计影响不同，本期默认日内盘中 + 日线收盘各扫一次，请确认。
4. **邮件发送账号**：QQ 邮箱 SMTP 是否已开启授权码模式（非登录密码）？收件邮箱与发件邮箱是否同一地址？
5. **回测数据源**：`quant_core.py` 依赖 pandas 未安装，回测数据走现有行情接口拉取历史 K 线即可，还是另有本地历史数据源？（默认：复用现有接口 + cache.py 缓存）
6. **资金规模与上限默认值**：单笔 1 万 / 单日 3 万的默认值是否符合实际资金量？白名单初始标的清单？
