## 一、这套界面解决什么问题

项目文档有 31 份、80 条关系，读者面对的是三个问题：

1. **该信哪一篇**——同一主题存在现状、计划、历史、归档四类文档，读错会导致按过期设计开发；
2. **改一处会牵动哪里**——引用关系隐藏在正文里，不打开文档看不见；
3. **哪条能力链是断的**——有 PRD、有架构、没有实施/交付，图上却看起来"都连着"。

AXON 把这三个问题编码进同一张仪器图版：**位置表示信息架构，颜色表示可信层级，连线表示引用与登记，读数区把缺口量化**。

## 二、设计编码（一套固定语义，不做装饰性用色）

| 维度 | 编码 | 依据 |
|---|---|---|
| 横向 7 列 | 根目录 → 00 战略 → 20 需求 → 10 架构 → 30 数据 → 40 运维 → 90 归档 | 按**决策链**排列，不按目录编号（PRD 先于架构） |
| 颜色 | 五类可信层级：真相源 / 生效计划 / 历史设计 / 归档 / 索引台账 | [`文档地图`](../00-strategy/README.md) 的分级规则 |
| 点径 | 被引用数（度数） | `docs-graph.json` 的 `degree` |
| 实线 + 箭头 | 正文引用（有向） | 文档正文里的显式 markdown 链接，可回溯行号 |
| 虚线 | 登记关联（无向） | [`project-docs-data.js`](../../static/js/project-docs-data.js) 的分组登记 |
| 强调色（暖金） | 只用于「权威」与「可交互」 | 避免与行情红绿语义冲突 |

五套材质：**墨金**（仪器纸）、**纸白**（印刷稿）、**石墨**（石墨灰 + 铜）、**素纸**（纯黑白）、**蓝图**（蓝晒图）。切材质只换 CSS 变量，不重绘图元。

## 三、交互模型：七个板块 + 一个筛选范围

| 板块 | 内容 | 可执行动作 |
|---|---|---|
| A 图版 | 7 列文档与 80 条关系 | 悬停看引用；点击开档案；双击进聚焦；点列头按层级筛 |
| B 读数 | 当前范围（文档/关系/平均度/密度）+ 全图口径 + 枢纽 TOP3 | 点「孤引」只看无正文引用的文档；点枢纽直接聚焦 |
| C 更新分布 | 7 个修订日 × 份数 + 最近修订 | 点柱 = 只看该日修订 |
| D 层间引用 | 7×7 矩阵 + 最强跨层 + 能力链 | 点格 = 只看这两层；点能力链 = 看链内文档与断点 |
| E 图例 | 五类层级（带份数）+ 两种线型 + 点径 | 点层级筛；点线型显隐该类边 |
| F 阶段 | 总体规划四阶段 + 日期区间 + 本阶段修订数 | 有修订的阶段可点筛 |
| G 题签 | 图版号 / 规模 / 生成 / 数据源 / 关系构成 / 比例 | 点比例复位 1:1 |

**唯一筛选范围** `{layer, date, pair, tier, phase, orphan, chain}`：任一板块改动范围，其余板块按同一范围重算（读数、分布、矩阵、图例份数、阶段计数、图版灰显、三维高亮）。范围 chip 可单独取消；`Esc` 逐级退出（面板 → 档案 → 聚焦 → 筛选 → 搜索）。

**档案（Dossier）**：任意文档的统计、摘要、章节、出链/反链、**连通性**（正文引用出/入、登记出/入、引用连通块大小）、**定位四键**（按层级 / 按修订日 / 按可信层级 / 聚焦）与同层最近文档。

## 四、三维视角（v6）

不是 CSS 斜切，而是自写的投影器：世界坐标 `(x, y, z)` → 绕 Y 旋转 → 绕 X 旋转 → 透视除法。

- **z 的两个来源**：层级沿视线做 ±7 的台阶级差；连线按两端度数拱起（34–130），形成"承重梁"；
- **自适应画幅**：每帧按纸面四角包围盒缩放居中；节点按投影深度做画家排序；
- **三种模式**：平面 / 轴测 / 动态（相机环绕 ±9°、指针视差、纸面起伏）；
- **降级**：`prefers-reduced-motion` 或「减少动效」→ 静态轴测；≤1240 视口（纵向清单）隐藏 3D 入口。

## 五、自动化中心 · 交易能力驾驶舱（v7.5）

看板 `dashboard.html` 的「自动化中心」（`automation.js`）之上增加一层只读驾驶舱
（`static/js/automation-cockpit.js` + `static/css/automation-cockpit.css`），不修改原脚本：

- **KPI 6 项**：今日信号、成交率、持仓/上限、仓位使用率、最大回撤、单日额度；
- **执行链路**：信号 → 决策闸 → 风控 → 下单 → 成交 → 复盘，点任一环节跳到对应 tab；
- **权益曲线**：`/api/review/equity` 的净值序列（带区间标注、绘制动画）；
- **策略门控**：5 个策略的状态、模拟天数进度、回测胜率；
- **拒单原因 TOP3 + 单笔/单日额度使用**：把"为什么下不出去单"直接摊开。

数据全部来自现有接口：`/api/automation/{gate,config,positions,orders,signals,review/metrics}` 与 `/api/review/equity`；15 秒内存缓存，面板打开时刷新。

## 版本之外：面板兼容规则（v8 确立）

1. **右侧抽屉同一时刻只开一个**：档案（dossier）与个性化（prefs）互斥，打开一个自动关闭另一个；
2. **滚动容器内的浮层必须能被收起**：自动化中心驾驶舱在视口高度 < 1100px 时不再吸顶，并支持「收起/展开」（状态存 `localStorage['axc-collapsed']`）；
3. **浮层不压交互区**：驾驶舱不覆盖 tab 栏与配置表单；3D HUD 仅在图区左上角、`pointer-events:none`；
4. **窄屏优先单层**：≤1240 视口下右侧栏改为图下三列、抽屉变底部浮层，任何时刻不出现双层抽屉叠加。

原版图谱的增强层可一键回退：删除 `static/project-docs.html` 中 `docs-graph-personal.css` / `.js` 两行即可；
驾驶舱同理（删除 `dashboard.html` 中 `automation-cockpit.*` 两行，或还原 `.bak-*` 备份）。

## 七、数据契约与维护流程

`static/docs-graph.json` 关键字段：`nodes[]`（id/path、group、group_label、kind、tier 由 [文档地图](../00-strategy/README.md) 规则人工策展、degree、bridge、community、lines、bytes、updated、role、summary、heads）、`links[]`（source/target/type: `link` 有向引用 / `data_link` 登记、line 可回溯源行）、`metrics`、`dates`、`phases`、`generatedAt`。

**新增/修改文档后同步图版（标准流程）**：

1. 写文档（`docs/**/*.md`），正文用显式 markdown 链接引用相关文档——引用关系由图谱自动提取；
2. 运行 `python tools/gen_docs_graph.py` 重新生成 `static/docs-graph.json`（纯标准库，可重复运行）；
3. 重新构建 AXON 图版：`node src/build.mjs`（`D:\轩\docs-graph-design`），把 `dist/index.html` 复制为 `static/plate-graph.html`；
4. 若为新文档，在 `docs-graph-design/src/build-data.mjs` 的 `CURATED` 表里补一行短码/中文名/可信层级；
5. 原版图谱 `docs-graph.js` 直接读同一份 JSON，无需额外构建。

## 十、系统界面统一（v13 · 2026-10-23）

| 问题 | 修复 |

## 十三、星系模式（v17 · 2026-10-23）

> 对标开源太阳系图集（solar-system-atlas）的"动态星系"语言：文件图谱不再只是被旋转的平面，而是一个**会公转的立体星系**。

### 1 · 结构

- **中央恒星** = 整份文档集的索引中心（带光晕/呼吸脉冲），文档不再有"中心节点"竞争；
- **7 条轨道** = 7 层信息架构（根 → 归档），轨道半径 = `92 + 层序×33`，双层倾斜交替（±0.1–0.15 rad）形成体积；
- **行星 = 文档**：大小按被引用度、颜色按可信层级、外环按文档类型、金色外环标记桥接文档；
- **尾迹** = 最近 22 帧的轨道残影，显示"运动方向"；
- **星场** = 260 颗远景星，随相机旋转视差；
- **公转**：外圈慢、内圈快（层级越高转速越快），在轨道面上下做 6 单位正弦起伏；`prefers-reduced-motion` 时停止公转但保留拖拽/缩放。

### 2 · 交互

- 拖拽 = **360° 环绕**（yaw 无限制，pitch 0.12–1.5）；
- 滚轮 = 锚点缩放；右键 / Shift+左键 = 平移；移动鼠标 = 光源与视差；
- 悬停行星高亮其引用连线，点击行星打开文档档案（pointerup + elementFromPoint 命中，修复了 capture 导致的点击失效）。

### 3 · 自查发现并修复的缺陷

| 缺陷 | 原因 | 修复 |
|---|---|---|
| 星系不公转 | `loop3D` 的 active 条件未包含 galaxy，rAF 在入场动画后停止 | active 加入 `cam.mode === 'galaxy'` |
| 减少动效无效 | 公转角速度未读取 `prefs.motion` | `reduce` 时 `t=0` |
| 行星拖尾无限增长 | 未限制历史长度 | 截断到 22 帧 |
| 自由视图线条糊成一片 | 93 条引用全画 | 星系/环幕/星图仅悬停时画连线 |
| 标签压住恒星 | 内圈标签统一右偏移 | 星系下标签径向外推 12 单位、阈值提到 degree ≥ 7 |
| 3D 点击无反应（v15 已修） | `setPointerCapture` 把 click 目标改成 SVG 根 | pointerup + `elementFromPoint` 命中 |

### 4 · 验收

- 星系：7 条轨道、33 颗行星、260 颗星、33 条尾迹、中央恒星呼吸；1.2 秒内行星投影位置变化（公转生效）；

- 1600 视口无控制台错误；页面 244 KB。

## 十九、星系鼠标稳定性修复（v23 · 2026-10-24）

### 1 · 现象

点击「星系」后，鼠标在图上移动（不按键），整幅画面会漂移/轻微缩放，观感上"不是稳定的立体空间"。

### 2 · 根因

1. 星系取景（scene transform）每帧**按节点投影包围盒重算**，而鼠标位置会通过 `parX/parY` 指针视差改变投影中心，导致包围盒变化 → 画面同时平移+缩放；
2. 相机在星系下仍有 ±0.02 rad 的"呼吸漂移"，进一步让每帧适配比例抖动；
3. 公转让节点位置持续变化，取景随之呼吸。

### 3 · 修复

- **稳定取景**：进入星系时按轨道几何（半径 92+6×33+74、垂直 ±42）算一次 `g3.galFit`，之后只用 `userZoom/pan` 变化，不再按每帧节点包围盒重算；
- **关闭星系指针视差**：`parX/parY` 在星系恒为 0，鼠标只控制光源与悬停，不移动相机；
- **关闭星系相机漂移**：`cam.ry/rx` 在星系只取 `base`（拖拽仍生效），动态全部交给公转/尘埃/彗星；
- **拖拽结束再取景一次**：旋转改变俯仰后重新计算一次，避免旋转后出画，且拖动过程中不抖。

### 4 · 验收

- 鼠标连续移动 4 个位置：scene transform **完全不变**（修复前 translate 移动 71px、scale 变化 1.2%）；
- 拖拽旋转仍生效、滚轮缩放 ×1.00 → ×1.62、悬停信息卡正常；
- 无控制台错误，页面 269 KB。

## 二十四、WebGL 星系层（v32 · 2026-10-24）

### 1 · 为什么要上 WebGL

2D Canvas 的粒子星系无论怎么调，点精灵都是硬边、无体积、无真实加色叠光，观感"低级"。
这一版把星系交给 GPU：原生 WebGL（无第三方依赖、仍单文件离线），CPU 每帧只更新矩阵和 uniform。

### 2 · 渲染管线

| 阶段 | 实现 |
|---|---|
| 体积星云 | 全屏 fragment shader：4 阶 fbm 值噪声 + 时间漂移 + 径向衰减，暖紫冷蓝混合 |
| 星系粒子 | 30k/16k/46k（标准/稀疏/密集）静态缓冲，顶点着色器按半径做**差速自转**（内快外慢） |
| 点精灵 | `gl_PointCoord` 圆形柔光，`pow(1-r,3)` 衰减 + 白热核；预乘 alpha |
| 加色混合 | `gl.blendFunc(ONE, ONE)`，颜色不爆白（此前用 SRC_ALPHA 导致白化） |
| 双层辉光 | 同一缓冲画两遍：主通道（size×1）+ 辉光通道（size×5、alpha 0.09）近似 bloom |
| 相机 | 自建 perspective + lookAt，yaw/pitch 跟随 `cam.ry/rx`，滚轮控制距离；拖拽带惯性 |
| 文档星 | 2D Canvas 层（与 SVG 署名共用 `project3` 坐标）：暖色 radial 光晕 + 白热核 + 十字星芒（引用越多星芒越长） |
| 注记 | 只标枢纽（degree≥8）+ 悬停/选中，标签贴着星体、短引线，其余悬停显示，避免满屏文字 |

### 3 · 回退

WebGL 不可用（旧浏览器/禁用 GPU）时自动回退 v31 的 2D Canvas 粒子星系，交互与数据完全一致。

### 4 · 性能（1600×1000，Chrome）

| 场景 | 平均帧间隔 | p95 | >33ms |
|---|---|---|---|
| 空闲 | 16.7 ms | 17.8 ms | 0 |
| 连续拖动 | 16.6 ms | 18.7 ms | 0 |

页面 296 KB（仍单文件、离线可开），无控制台错误。

### 5 · 待继续

## 二十五、真 bloom + ACES 合成 + 体积尘埃（v33 · 2026-10-24）

### 1 · 后处理管线（GLSL，原生 WebGL）

场景不再直接画到屏幕，而是：

1. **场景 RT**：星云 + 粒子先渲染到全分辨率 FBO；
2. **亮部提取**：半分辨率 FBO，阈值 0.34，`luma` 超阈值部分保留；
3. **分离高斯**：水平/垂直各一遍 5-tap 高斯（半分辨率），两次迭代；
4. **ACES 合成**：`scene + bloom × 1.05` → ACES filmic 曲线 → gamma 2.2 → 屏幕；
5. **暗角**：合成时按屏幕半径 `smoothstep(1.28, 0.32)` 压暗边缘（0.55–1.0），收拢视觉重心。

拖动时自动降级：跳过亮部/模糊，仅做 ACES 合成，保交互帧率。

### 2 · 体积尘埃

- 沿旋臂追加 160 颗**巨型低亮精灵**（尺寸 34–104），暖/冷两色，与星尘同缓冲、同差速自转；
- 配合 bloom 产生"云气透光"的体积感，填补旋臂间的空洞；
- 背景 fbm 星云颜色改为深冷蓝（`#05070b`→`#0e0f1c`→`#1f1a12`），去掉上一版的紫色泛光。

### 3 · 文档星与署名

- 文档星在 2D 层用暖色 radial 光晕 + 白热核 + 十字星芒绘制（引用越多星芒越长），与 SVG 署名共用 `project3` 坐标；

## 二十六、回归「仪器图版」：制图版星系（v34 · 2026-10-24）

### 1 · 设计问题不在"亮不亮"，在于跑偏了世界观

`DESIGN.md` 明确定义这张图的世界是**仪器图版 / 制图手册**（深色纸面、发丝线、颜色只表可信、金色只表权威）。

### 2 · 制图版化改造

| 项 | 改法 |
|---|---|
| 星云 | 强度压到 0.35，只作纸面底色，不再抢主体 |

| 粒子 | 尺寸缩小、亮度提高：形成"刻点"而不是"噪点" |
| 版式 | 新增 7 条**同心层环**（对应 7 个层级半径）+ 72 根外圈刻度 + 四角角标 + 图签 `PLATE 07 · DOCUMENT CONSTELLATION / 33 STARS · 93 RELATIONS` |

| 配色 | 暖金核 + 钢蓝臂 + 近黑纸面，去掉紫雾 |

### 3 · 结果

- 星系从"发光壁纸"变成"制图版上的星图"：有层环、有刻度、有角标、有图签，所有元素可回指数据（层级/引用/可信）；

### 4 · 仍可继续

## 三十、银河系 3D 动态图谱（v38 · 2026-10-24）

### 1 · 设计理念落地

用户的设计理念是**银河系 3D 动态图谱**。此前是"盘面 + 倾斜的二维旋臂"，这一版改成真正的三维银河：

| 结构 | 生成方式 | 视觉 |
|---|---|---|
| 核球 Bulge | 1.1 万颗粒子，棒状分布（bar 角 -0.55 rad，x×1.45 / z×0.72），r = pow(rand,2.4)×118 | 暖金高密度核心 |
| 银盘 Disk | 4.2 万颗，指数径向 + 4 条对数旋臂 + 厚度 `(rand+rand+rand-1.5)×(4+t·9)` + 翘曲 `sin(2θ)·t·10` | 蓝白年轻星 + 暖黄老星，有厚度、有翘曲 |
| 银晕 Halo | 5 千颗球状稀疏老星，半径 280–740 | 暗银外围晕 |
| 文档星 | 34 颗，kind=1 标记，按层级半径落在旋臂上，颜色随可信层级 | 亮星 + 十字星芒 |

### 2 · 与 SVG 层严格对齐

GL 顶点着色器改为与 `project3()` 完全一致的**伪透视**：
先绕 Y 旋转 yaw、再绕 X 旋转 pitch，然后 `s = d / max(260, d − z)`，屏幕坐标 = `p.xy × s × zoom`。
这样 WebGL 银河与 SVG 文档星、署名、引线共享同一投影，鼠标悬停/引线/标签不再错位。
自转在顶点着色器内完成（`uTime × uSpin`），CPU 每帧只更新 uniform。

### 3 · 相机与交互

- 倾斜到低仰角时可见银盘厚度与核球立体感；
- 悬停文档星显示信息卡、引用弧；点击打开档案；
- 与 v35 个性化（四套外观 / 色调 / 质感 / 种子 / 辉光 / 底纹）完全兼容。

## 三十九、悬臂星系（v46 · 2026-10-25）

### 1 · 动机

v45 的制图美学解决了配色与装饰噪声，但用户仍不满意画面。诊断出**结构性根因**：

读起来仍是"圆圈上的点"，不是星系。

### 2 · 结构重设计

**单臂对数螺旋**：`θ(r) = 3.3·ln(r/r₀)`。

| 维度 | 映射 |
|---|---|
| 半径 | 板块层带中心 `ringR(li)` + 层带半宽 31% 内的径向抖动 |
| 角度 | 螺旋相位 `spiralTheta(r)` + ±0.23 rad 抖动 + 整体自转 |
| 高度 | 纵深维度 depthY + 随半径收薄的盘面散布 |

35 颗星由此连成**一条清晰旋臂**（评审确认"星点连成弧线，不再是散点"）。

### 3 · 配套视觉

- **银河带辉光**：沿螺旋铺 46 团暖光（前亮后暗、外段渐宽），旋臂有了"光带"的身体；
- **层带引导弧**降为发丝级（α 0.16/0.05），只作半径标尺；外圈量表刻度外移至层带外缘；
- **核心**加 130px 宽晕，悬臂自它展开，体量感成立；
- **选中层带**强化：整带充色 + 螺旋段提亮（bandK 半径判定）；
- 交互保持：层带命中 `ringAt` 改为带状采样（内/中/外三圈，容差 9px——相邻带中线间距 ~41px，
  一点至多命中一带），点带选板块、悬停高亮、双击复位全部如旧；
- 评审采纳：小星半径抬底（2.4）、纵深标尺文字对比度提升。

### 4 · 验收

- 视觉评审：**9/10**——"旋臂结构让星系有真正的结构感与生命力，高级感与辨识度显著提升"；

## 七十五 · 浑天仪拖拽的「空间维度」修复：三环姿态 + 屏幕轴旋转（v85 · 2026-11-02）

**现象**：用户反馈星系（浑天仪）拖拽仍有死角，「某些角度拖了像没动 / 松手还在飘 / 侧栏抓不住」。

**实测**（Playwright，关自转与动效以隔离环境动画，指标=全部星点平均屏幕位移）：

| 姿态 / 手势 | 修复前 | 修复后 |
|---|---|---|
| 基准·水平拖 100px | 73.7px | 73.7px |
| 极点(90°)·水平拖 | 22.9px | **80.1px** |
| 超极点(180°)·水平拖 | 18.9px | **63.2px** |
| 右侧说明栏起拖 | 3.3px | **64.0px** |

**根因（三条，均有测量支撑）**

1. **两环欧拉在极点退化**：只有「航向 ry + 俯仰 rx」，且 ry 绕**世界 Y 轴**。俯仰接近 ±90° 时世界 Y
   与视线轴重合，水平拖拽退化为**绕视线轴自转**——星系盘近似轴对称，看起来就是「没动」。
2. **拖拽增量被渲染循环二次累加**：拖拽设绝对值的同时写 `cam.vry/vrx`，`loop3D` 每帧再叠加并衰减，
   松手后继续自转（实测 3.25s 仍漂移 8.6px）。
3. **按钮区域被排除**：`DRAG_BLOCKERS` 含 `button`，而右侧说明栏几乎全是 `button.panel-row`，
   从栏内起拖根本不进入拖拽分支。

**修复**

* 增加**第三环滚转 `rz`**（`R = Ry·Rx·Rz`），`project3` 在俯仰后追加滚转；
* 拖拽改为**屏幕轴旋转**：预乘 `Ry(ax)·Rx(ay)` 再分解回三环，左右=绕屏幕竖轴、上下=绕屏幕横轴，
  任意姿态跟手且仍可无限环绕（不 clamp）；
* 拖拽期间 `loop3D` 跳过惯性分支；`DRAG_BLOCKERS` 移除 `button`（按下不动仍是 click，移动 >5px 才吞 click）；
* 顺手删掉 `COSMO / galaxyArms / galaxySpinAngle` 的**重复定义**（历史合并残留）。

**验收**：`scripts/verify/verify_armillary_drag.mjs` **17 PASS / 0 FAIL**。
指标刻意不用质心位移——平坦盘绕屏幕竖轴转，几何上是「压扁」而非平移，质心会误判；
改用「运动能量 + 点云主轴比变化（排除原地自转）+ 近轴跟手方向」三项。
