# 数据平台与数据源治理（2026-10-30）

> 目标：让「数据从哪来、可不可信、坏了怎么办」有唯一答案。任何面板/策略/指标都必须能追溯到来源与时间。

## 一、数据源注册表（当前实测）

`GET /api/data-sources/health` 返回统一健康状态（实现：`server/datasources.py`）。

| key | 数据源 | 角色 | 当前状态（2026-10-30） | 降级/替代 |
|---|---|---|---|---|
| tencent | 腾讯行情 `qt.gtimg.cn` | 实时指数/个股快照（**critical**） | ok | 新浪行情 |
| sina | 新浪财经全市场列表 | 题材雷达/全市场名称涨跌（**critical**） | ok | 腾讯批量 |
| eastmoney_datacenter | 东财数据中心 | 龙虎榜、财经要闻、部分资金数据 | ok | 新浪要闻、缓存快照 |
| eastmoney_push2 | 东财 push2 | 板块/资金流实时 | **degraded**（当前网络被阻断） | 本地板块快照 + 成分股聚合 |
| tdx_local | 通达信本地 `vipdoc` | 离线历史日线/分钟线 | degraded（未安装） | 腾讯/新浪 K 线 |
| tushare | Tushare Pro | 基本面/日线可选主源 | degraded（无 token） | 东财/腾讯 |

`critical_ok=true` 表示核心实时源可用；`degraded` 不等于不可用，而是需要替代路径或缓存。

## 二、数据分层与缓存

| 层 | 内容 | 现状 |
|---|---|---|
| L0 原始源 | 腾讯/新浪/东财/通达信/Tushare | 直连，`NO_PROXY=*`（浏览器代理不影响服务端） |
| L1 端点缓存 | `server/cache.py` TTL 缓存、熔断 | 已有，按接口 TTL |
| L2 快照 | `data/sector_map.json`、`sector_periods.json`、`market-dashboard` 快照 | 已有；快照日期必须在 UI 标注 |
| L3 历史/离线 | 通达信 `vipdoc`、`data/trading.db` | TDX 读取已实现；交易 DB 已有 |
| L4 决策产物 | 决策卡、复盘、经验库 | localStorage + 自动化 DB；后续统一入库 |

## 三、口径与质量标记（强制）

1. 每个接口返回 `source`（来源）、`as_of`/`update_time`（时间）、`degraded`/`stale`（降级标记）；
2. 面板展示旧数据时必须显示「快照/降级 + 日期」，禁止把旧数据当实时；
3. 涨停统计用「涨幅≥9.7%」近似（20cm 板同样计入），文档与 UI 都要写明；
4. 板块历史收益来自本地快照时，必须显示 `board_snapshot_as_of`；
5. 北向资金自 2024-08 起不再实时披露：展示结构指标（成分股涨跌）并注明原因，不造净流入数字。

## 四、数据源接入优先级（下一步）

1. **Tushare Pro**（最高优先）：日线/财务/指数成分，token 放 `.env` 的 `TUSHARE_TOKEN`；
   - 优点：字段规范、可复现、适合回测与基本面；
   - 注意：积分限制，先做日线+财务摘要，避免全量高频。
2. **通达信本地数据**：安装客户端 + 盘后数据下载，`TDX_HOME` 指向安装目录；
   - 优点：完全离线、历史完整、免费；
   - 限制：需 Windows 客户端定期下载，Linux 云服务器不可用（可保留本地电脑做数据准备）。
3. **百度股市通/雪球等**：仅作为补充，不作为 critical（接口非官方、易变）。
4. **券商 Level-2 / 付费数据**：有预算再上，先解决"有没有"再解决"快不快"。

## 六、治理规则

- 新增数据源必须登记到 `server/datasources.py`，并在本文档补一行；
- 新增面板必须显示来源与时间；无来源的"估算值"不得进入决策卡；
- 任何数据源失效先查 `/api/data-sources/health`，再决定切换/缓存/告警；
- 数据修复与口径变更必须写 CHANGELOG 与本文档。
