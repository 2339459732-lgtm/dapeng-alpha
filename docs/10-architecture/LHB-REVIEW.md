## 一、它解决的问题与边界

龙虎榜给的是「谁买了多少」，不回答「为什么」。复盘的价值在于把**行为**翻译成**动因假设**，
并让这个假设可被后续走势检验。所以本模块只做两件事：

1. **还原**：谁（席位）、买了/卖了什么（标的、方向、金额、占比）、什么价（收盘 vs VWAP）、什么时点（封板时间）；
2. **归因**：在五个维度上打分，取最高者为主因，并给出可审计的证据链。

**必须先讲清的三条边界**（报告 `caveats` 里也逐条写了）：

| 边界 | 影响 | 模块的处理 |
|---|---|---|
| 龙虎榜**没有逐笔时间** | 无法知道具体几点几分成交 | 能取到涨停封板时间时输出 `inference: "seal-time"`（封板时刻推断）；否则 `inference: "day-level"`（日级推断）。两者都不是分时证据 |
| 营业部→游资别名是**市场俗称** | 「赵老哥」未必真是那个人 | `alias_source` 逐条标注，机构/北向标「交易所披露」，游资标「市场俗称（未逐条核实）」 |
| 动因是**规则打分的启发式结论** | 不是因果证明 | 每条记录带 `confidence` 与完整 `evidence`，可逐项复核；报告声明不构成投资建议 |

## 二、数据源与字段

| 用途 | 接口 | 关键字段 | 口径说明 |
|---|---|---|---|
| 营业部买卖明细 | 东财 `RPT_BILLBOARD_DAILYDETAILSBUY` / `...SELL` | `OPERATEDEPT_NAME`、`BUY`、`SELL`、`NET`、`RISE_PROBABILITY_3DAY`、`TOTAL_BUYER_SALESTIMES_3DAY`、`TOTAL_BUYRIO` | **营业部级**，买五卖五分列；含该席位 3 日成功率与样本数 |
| 个股级龙虎榜 | 东财 `RPT_DAILYBILLBOARD_DETAILS` | `EXPLANATION`（上榜原因）、`ACCUM_AMOUNT`、`FREE_MARKET_CAP`、`TURNOVERRATE` | 提供上榜原因与真实换手率 |
| 涨停 / 炸板 / 跌停池 | akshare `stock_zt_pool_em` / `_zbgc_em` / `_dtgc_em`（东财同口径） | `连板数`、`首次封板时间`、`最后封板时间`、`炸板次数`、`换手率`、`所属行业` | **按复盘日取**，见下文「时间轴」 |
| 公告 | `np-anotice-stock.eastmoney.com` | `title`、`notice_date`、`columns[].column_name` | 窗口锚定复盘日，不接受复盘日之后的公告 |

### 三个容易踩的口径坑

**1. `TOTAL_BUYRIO` 是小数，不是百分数。** 上游返回 `0.0211` 表示 2.11%，直接当百分比展示会差 100 倍。
输出统一换算成 `buy_ratio_pct: 2.11`。

**2. 涨停池必须按复盘日取，不能用「当前广度」。** 复盘 11-02 的榜时若用当时盘中的涨停家数，
时间轴就错了一天——用 T+1 的现象解释 T 的行为。`fetch_limit_pools(date)` 按日期取，天然对齐。

**3. 个股级接口不给 `ACCUM_VOLUME`。** `RPT_DAILYBILLBOARD_DETAILS` 只有成交额，没有成交量，
算不出 VWAP；营业部明细行里有 `ACCUM_VOLUME`。所以 `_stock_meta_from_row()` 在个股行缺失时
回落到营业部行——同一天同一只票，口径一致。

## 三、席位筛选：谁才值得跟

`classify_seat()` 把营业部名映射成五类，顺序**有讲究**：

```
机构专用 → 北向（沪股通/深股通/港股通） → 散户关键词（拉萨…） → 游资名单 → other
```

> 散户关键词必须排在游资名单**前面**。拉萨天团在 `hot_money` 名单里也有一条，
> 但它的性质是散户集中席位（`quality=false`）。先查名单的话，它会被当成优质游资混进复盘。

筛选门槛（`data/lhb_config.json` → `quality`）：

| 席位类型 | 保留条件 | 理由 |
|---|---|---|
| `institution` | 净额 ≥ `institution_min_net`(5000 万) | 机构单笔金额大，门槛更高才有区分度 |
| `northbound` / `hot_money` | 净额 ≥ `min_net_amount`(3000 万) | 名单与通道本身已经是身份背书 |
| `retail` / `other` | 净额 ≥ 3000 万 **且** 3 日成功率 ≥ 50% **且** 样本数 ≥ 30 | 没有身份背书，只能靠历史成功率；但成功率 100% 只出现过 2 次是噪声，不是能力 |

## 四、五维归因：每一项只算一件事

八个维度全部归一到 `[0, 1]`，取最高者为主因，次高者（≥`min_primary_score`）列为次要因素。

### 4.1 题材炒作 —— 只算板块效应

只用**同行业当日涨停家数**，以及该行业是否当日最强前三。

| 条件 | 加分 |
|---|---|
| 同行业涨停 ≥ `hot × 2`（默认 6 家） | +0.70 |
| 同行业涨停 ≥ `hot`（默认 3 家） | +0.45 |
| 同行业涨停 ≥ 2 家 | +0.25 |
| 该行业为当日涨停家数前三 | +0.15 |

> **为什么连板高度不在这里**：连板高度是「情绪周期 / 龙头效应」的证据，属于市场情绪维度。
> 两个维度都吃连板数会重复计分，同一件事被算两遍，主因就永远偏向其中一边。

不在涨停池里的标的不给分（`无行业归属 → 0`），不猜行业。

### 4.2 市场情绪 —— 环境打折 + 龙头效应

这一维拆成两半，因为它们的**区分度完全不同**：

**环境分（全市场同一个值）**：涨停家数、空间高度（最高连板）、封板率。
这一半对当天所有标的一模一样，本身不能区分个股。若原样参与比较，一个 125 家涨停的日子
会把 40 条记录全部归因成「市场情绪」，归因就失去意义。所以按 `mood.discount`（默认 **0.55**）打折。

**龙头效应（个股特异）**：

| 条件 | 加分 |
|---|---|
| 连板数 = 当日最高板（且 ≥2 板） | +0.35 → 「情绪龙头（空间标杆）」 |
| 连板数 = 最高板 − 1（且 ≥2 板） | +0.20 → 「二线龙头」 |
| 为所在行业最高板（且 ≥2 板） | +0.12 → 「题材龙头」 |
| 炸板 ≥1 次后回封 | +0.08 → 「人气有承接」 |

打折后仍然胜出，说明该股确实没有个股级证据。此时 `motive.mood_only = true`，
`confidence` 上限压到 0.45，`logic` 里明确写：

> 注意：个股层面无特异证据（题材/博弈/消息/技术均未达标），该归因属环境驱动，
> 仅说明当日情绪允许这类资金出手，不代表个股自身逻辑

### 4.3 资金博弈 —— 看方向，不看「同时存在」

| 条件 | 加分 |
|---|---|
| 榜内净额 / 成交额 ≥ 10%（`net_ratio_extreme`） | +0.50 |
| 榜内净额 / 成交额 ≥ 5%（`net_ratio_strong`） | +0.30 |
| 机构 与 游资/北向 **方向相反** | +0.30 |
| 同席位买卖双向（对倒迹象） | +0.30 |
| 单一席位占榜内净额 ≥ 60% | +0.20 |

两个坑：

- **「机构与游资同榜」不等于博弈**。龙虎榜买五卖五摆在那，几乎天天都同时存在。
  必须按席位类型汇总净额、方向相反才算对手盘。
- **对倒检测不能用「分侧」判断**。`build()` 已经把同一席位合并成一行，
  按 `BUY >= SELL` 分买卖侧永远只会得到一侧，判定必然为空。正确做法是
  `BUY > 0 and SELL > 0`（合并后两侧都非零才是真双向）。

### 4.4 消息面 —— 高信号 × 时效衰减

分两档关键词，按距复盘日天数衰减：

| 档位 | 关键词（示例） | 基础分 |
|---|---|---|
| 高信号 | 重组、并购、中标、业绩预增、涨价、停牌、问询、立案、控制权、定增、重大合同 | 0.40 |
| 次信号 | 签订协议、关联交易、对外担保、回购、减持、增持、重大诉讼 | 0.20 |

| 距复盘日 | 系数 |
|---|---|
| ≤1 天 | 1.00 |
| 2–3 天 | 0.75 |
| 4–5 天 | 0.50 |

命中多条同类公告时每条 +0.10（最多 +0.20）。

> **为什么不衰减**：三天前的「中标公告」和当天早上的「中标公告」，对当天打板的解释力完全不同。
> 不衰减的话，只要窗口里有公告就一律满分，消息面会变成「最近几天发过东西」的同义词。
>
> **为什么窗口必须锚定复盘日**：复盘 11-02 的榜在 11-05 才跑，用 `now` 会把 11-03~11-05 的公告
> 算进 11-02 的动因里——典型的未来函数。`_announcements(..., as_of=date)` 强制按复盘日截断。

### 4.5 技术形态 —— 封板质量，不是涨跌幅

数据优先取涨停池（打板场景真正关心的三个字段只有它给）：

| 条件 | 加减分 |
|---|---|
| 收盘涨停 | +0.30 |
| N 连板（N≥2） | +min(0.35, 0.15 + 0.05N) |
| 全天未炸板 | +0.10 |
| 炸板 ≥3 次 | **−0.20**（封板质量差，分歧剧烈） |
| 换手 ≥20%（`turnover_extreme`） | +0.40 |
| 换手 ≥10%（`turnover_hot`） | +0.25 |

不在涨停池的标的，用交易所**上榜原因**判断异动性质（`EXPLANATION`）：

| 上榜原因含 | 调整 |
|---|---|
| 「跌幅」 | −0.10 → 弱势异动，非进攻形态 |
| 「连续三个交易日」 | +0.20 → 多日持续异动，非单日脉冲 |
| 「振幅」 | +0.10 → 多空分歧剧烈 |
| 「换手率」 | +0.12 → 筹码大换手 |

> 没有这段，非涨停股的动因只能落到「情绪」上，归因会趋同。
>
> 换手率的口径也要分清：涨停池的 `换手率` 是真实换手；`stock_meta["turnover"]` 的回退值
> 是「上榜成交额 / 流通市值」，分母口径不同，只能当降级估算，note 里会标 `（上榜额/流通市值估算）`。

## 五、同分时的优先序

`sorted()` 是稳定排序。若只按分数排，`mood` 在字典里排在 `theme` 后面、`game`/`news`/`technical` 前面，
凡是同分的记录会莫名其妙全落到「市场情绪」。

所以显式定义 tie-break：**个股特异证据优先，全市场共用的情绪最后**。

```
theme(0) → game(1) → technical(2) → news(3) → mood(9)
```

### 推断等级（`price_context.inference`）

| 值 | 含义 | 前置条件 |
|---|---|---|
| `seal-time` | 用**涨停封板时间**推断买卖时点 | 该股在当日涨停池里且有 `首次封板时间` |
| `day-level` | 只能定性到「盘中 / 板上 / 尾盘」 | 其余情况 |

`seal-time` 的文案举例：

- 买入 + 10:37 才封板 → 「买入更可能发生在盘中拉升段而非一字板上」
- 买入 + 09:32 封板 → 「买入更可能发生在封板前抢筹或封板瞬间排队」，若当日开过板则补「也可能在回封时介入」
- 卖出 + 首封 11:22、最后封板 11:24 → 「卖出更可能发生在开板区间或尾盘炸板时（板上兑现需要承接）」
- 卖出 + 首封后未再开板 → 「卖出更可能是板上排队成交（板上兑现）」

## 七、买卖因素库（`server/lhb_factors.py` / lhb-factors.v1）

五维归因回答「这笔钱为什么出手」的**维度**；因素库回答更直接的问题：**此刻具备哪些买入条件、哪些兑现条件**。
两者是不同的颗粒度——「主因是资金博弈」是归类，「炸板 2 次 → 开板兑现窗口」是可核对的判定式。

### 7.1 为什么做成配置而不是代码

早先「为什么买/为什么卖」是写死在 `attribute()` 里的 if 拼接，问题有三个：

1. **不可调**：牛市级别的接力理由在退潮期是陷阱，但改一句文案要改代码发版；
2. **不完整**：只有 4~5 个条件，尾盘偷袭封板、炸板回封、主线板块追涨、均价下方低吸描述不出来；
3. **不可统计**：文案是字符串，没法回答「哪类买入理由次日更容易被打脸」。

现在每条因素是 `id + label + weight + when` 的判定式，全部在 `data/lhb_config.json` 的 `factors` 段可调。

### 7.2 判定式语法

`when` 的键是「事实名 + 比较符后缀」，值是比较对象，多键之间 **AND**：

```json
{ "id": "seal_early", "label": "早盘封板抢筹", "weight": 0.8,
  "when": { "is_limit_up": true, "first_seal_lte": "10:00" } }
```

- 后缀：`_gte`（≥）`_lte`（≤）`_gt`（>）`_lt`（<）`_eq`（==）`_ne`（!=），无后缀即相等；
- 时间字段（`first_seal` / `last_seal`）是零填充 `HH:MM`，字符串比较等价于时间比较；
- **事实缺失（None）不命中**——「不知道」≠「不满足」，不用 0 顶替；
- 配置引用了不存在的事实名：fail-closed（不命中），绝不静默通过；
- `weight` 只用于排序与主因素选择，不做概率解释。

可用事实表（`facts_from()` 从 price_context / stock_meta / 五维分数 / 市场上下文收拢，只放已有事实）：
`is_limit_up` `board_count` `open_times` `first_seal` `last_seal` `turnover` `chg` `close` `vwap`
`vwap_gap_pct`（收盘偏离均价 %）`industry_rank` `peers` `news_score` `game_score` `theme_score`
`technical_score` `mood_score` `net_ratio`（榜内净额占成交额 %）。

### 7.3 默认因素（6 买 + 6 卖）

| 买入侧 | 触发条件 | 卖出侧 | 触发条件 |
|---|---|---|---|
| 早盘封板抢筹 0.8 | 涨停且首封 ≤10:00 | 开板兑现窗口 0.7 | 炸板 ≥1 次 |
| 主线板块追涨 0.7 | 同行业涨停 ≥3 且行业排名 ≤3 | 板上兑现 0.6 | 收盘涨停 |
| 连板梯队接力 0.6 | 2 板及以上 | 换手过高出货 0.6 | 换手 ≥20% |
| 实质消息驱动 0.6 | news_score ≥0.4 | 题材发酵高点兑现 0.5 | theme_score ≥0.4 |
| 炸板回封承接 0.5 | 涨停且炸板 ≥1 次 | 博弈激烈触发 0.5 | game_score ≥0.5 |
| 均价下方低吸 0.4 / 高换手活跃票 0.3 | 偏离均价 <0 / 换手 ≥10 | 大幅偏离均价 0.4 | 偏离均价 ≥8% |

### 7.4 关键设计：对标的评估，不是对记录判断

`evaluate()` 对同一只票**同时**评估买卖两侧——同一只票可以同时「具备买入理由」和「具备兑现条件」，
这正是分歧的来源。所以：

- 每条记录带完整 `factors`（buy / sell / primary_buy / primary_sell / balance），明细里两侧成对展示；
- `balance = 最强买入权重 − 最强卖出权重`：正 = 买入理由占优，负 = 兑现条件占优，接近 0 = 分歧；
- **统计口径按方向过滤**（`insight.factor_stats`）：买入侧只计买入记录的命中、卖出侧只计卖出记录的命中，
  否则买入记录的兑现条件会混进「为什么卖」；
- 买入时机文案追加「买入侧因素链（按权重）」，卖出触发改为逐条因素 + 各自证据
  （哪个条件、什么阈值），不再是一句笼统总结。



`records` 是「谁在哪只票上做了什么」的平铺清单。平铺清单看不出三件事，所以单独一层做**横切重组**
（不新增因果判断，只重排 + 少量可验证派生量）：

| 视角 | 回答什么 | 关键派生量 |
|---|---|---|
| `by_stock` | 一只票上多路资金是合力还是对峙 | `alignment`（合力做多 / 合力出货 / 多空对峙）、`buy_share`、`seal`（封板质量）、`motive`（|净额|加权） |
| `by_seat` | 一个席位当日是集中狙击还是分散试仓 | `focus`、`top_share`、`is_channel` |
| `by_industry` | 钱往哪些题材去 | 按行业汇总净额；未涨停的归「未归入涨停池」 |

另有 `motive_matrix`（主因 × 方向计数）、`motive_by_seat_type`（席位类型 × 主因）、
`highlights`（自动提炼的要点陈述）与 `totals`（汇总数字）。

### 8.1 合力判定

按「净买额 / 买卖总额」划分：

| 比例 | 判定 | 含义 |
|---|---|---|
| ≥ 80% | 合力做多 | 上榜席位几乎全在买，方向一致 |
| ≤ 20% | 合力出货 | 反之 |
| 其余 | 多空对峙 | 双方都有实质金额，次日方向取决于谁先松手 |

> 为什么不用「买入选手数 > 卖出席位数」：一家机构砸 3 亿、五家游资各买 2000 万，
> 按人数是「5 > 1 做多」，按金额是巨额净卖出。打板复盘关心的是钱的方向，不是人头。

### 8.2 通道 ≠ 交易者

`机构专用` / `北向资金` 是**通道汇总**，背后是几十上百个互不相干的账户。
把它们当成「一个人」去算集中度，得到的是当日上榜金额的分布，不是任何人真实的仓位动作。
所以：

- `is_channel: true`，`focus` 固定为「通道汇总」，`top_share` 返回 `null`（不给假的集中度）；
- 「最集中席位」这条要点只从**具名营业部**里选；
- 沪股通与深股通按**类型**合并成一行「北向资金」，`seat_raw` 保留两个入口名备查。

> 反过来，具名营业部的集中度是有意义的：单票占比 ≥60% 集中狙击、≤35% 分散试仓，
> 这是判断游资打法最直接的一个量。

### 8.3 主因按金额加权

标的与席位的主因取「|净额| 加权」，不是「记录条数投票」。
一家机构砸 3 亿卖出的理由，比一个席位买 3000 万的理由重要得多；
按条数投票会让小额记录淹没主要矛盾。

### 8.4 为什么单独一层

1. `lhb_review.py` 已接近 900 行上限（架构守卫的阈值），塞进去会越界；
2. 抓取 / 归因 / 聚合的变化节奏不同，混在一个文件里改一边要重读另一边；
3. 聚合是纯函数（输入 `records` + 原始 `context`），可脱网单测与回放。

> **传参陷阱**：`aggregate()` 必须拿到**原始** `context`（含 `zt` 逐票行业），
> 不能传 `report["context"]`——后者是给前端看的精简版，只有计数没有行业，
> 传错会让所有标的都落到「未归入涨停池」。

⑪ 口径与边界      与报告 caveats 一致

### 9.3 展示上的三个约定

1. **先给结论，细节按需展开**。默认只渲染概览与列表，35 条明细的详情点开才出现——
   一屏塞满文字反而读不出重点。
2. **每个数字都带口径**。金额在「万 / 亿」间自适应；封板时间标「首封」；
   推断等级（`封板时刻` / 日级）直接标在行内，不让人误以为有分时成交。
3. **筛选即钻取**。点主因条、点标的行、点要点卡片，都把明细表收敛到对应子集，
   而不是跳到另一个页面；`重置` 一键回到全部。

### 9.4 一个必须记住的样式坑

`dashboard.css` 为了让主控台是「整屏应用」，给 `html,body` 设了 `height:100%; overflow:hidden`。
新页面如果直接复用这套样式又不解除，会变成**完全无法滚动**——首屏以下的面板用户永远看不到，
而且 Playwright 点击会自动滚动元素进视野，交互测试全过、真实用户卡死。所以本页显式覆盖：

```css
html { height: auto; overflow: visible; }
html, body.lr-body { min-height: 100%; }
.lr-body { height: auto; overflow-y: auto; }
```

## 十一、收盘后自动触发

`server/brain.py` 注册任务：

```python
"lhb_review": BrainTask(
    "lhb_review", "龙虎榜复盘", 1800, self._task_lhb_review,
    window=((15, 35), (23, 0)), weekdays_only=True,
)
```

**为什么 15:35 开始而不是 15:00**：营业部明细披露有滞后，通常 18:00~19:00 才补齐；
15:35 先跑一次拿到涨停池与首批席位，之后每 30 分钟重试，幂等覆盖同一份 JSON。

**两道止损闸门**（防止重试变成空转）：

| 闸门 | 触发条件 | 为什么需要 |
|---|---|---|
| 完成后停 | 记录数 ≥30，**或** 19:00 之后已生成过结果 | 只按记录数判断的话，清淡日子只有 20 条记录，会一路重跑到 23:00 |
| 失败后停 | 同一日期连续 3 次「无数据」 | 节假日当天永远没有数据，没有闸门会白打 15 轮上游请求 |

## 十四、已知限制与后续

| 限制 | 现状 | 后续 |
|---|---|---|
| 无逐笔时间 | 封板时间级 / 日级推断 | 若接入分时成交（L2 逐笔），可把 `inference` 升到 `tick` |
| 非涨停股无行业归属 | 题材维度给 0，标归「未归入涨停池」 | 接入行业成分表，按行业映射补上 |
| 游资别名未核实 | `alias_source` 标注 | 建立可追溯的别名登记表，带来源链接与生效区间 |
| 单日快照 | 只看当天 | 席位历史胜率、同席位连续多日行为追踪（需跨日聚合） |
| **缺少次日验证** | 只有 T 日归因，没有 T+1 结果回填 | 次日收盘后用涨跌幅回填「主因是否被验证」，这是复盘闭环最关键的一环 |
| 具名营业部样本薄 | 当日只有 1 家通过筛选（机构/北向占绝大多数） | 放宽 `other` 门槛或引入席位历史库，让营业部画像更可用 |
| 页面无导出 | 只能在页面看 | 复用 `scripts/review/build_review.py` 的输出能力，加「导出 Markdown / Excel」 |
| 只覆盖 A 股 | 沪深京 | 港股通标的需另一套席位口径 |
