## 第 0 章 · 战略定位与发展目标

### 0.1 一句话定位

**DAPENG Alpha 是一套面向 A 股的「可解释决策辅助系统」** —— 它把行情、板块、资金、全球市场、因子与策略信号收敛成**可追溯的决策依据**，再由自动化交易中心在**严格风控**下执行，并用复盘闭环反哺策略。

关键定语是"**辅助**"与"**可解释**"。系统的价值不在于预测明天涨什么，而在于让每一个买卖动作都有据可查、有错可溯、有据可改。

### 0.2 三层价值主张

| 层次 | 用户问题 | 系统回答 |
|---|---|---|
| 看得清 | 现在市场什么状态？ | 大盘纵览 / 板块轮动 / 全球联动 |
| 想得明 | 为什么是这些票？ | 因子分解 + 策略信号 + 缠论结构 + AI 主脑归因 |
| 做得稳 | 该不该动手？怎么控风险？ | 九关风控 + 自动化执行 + 复盘归因 |

### 0.3 北极星指标（衡量系统是否在变好）

沿用 `server/routers/review.py:166` 已实现的 6 项，本规划补充第 7 项：

1. **可回溯率** —— 每笔交易都能追到信号 ID 与策略 ID（当前 `orders.signal_id` / `trade_reviews.signal_id` 已具备）
2. **决策胜率** —— 闭合交易盈利笔数占比
3. **盈亏比** —— 平均盈利 / 平均亏损
4. **最大回撤** —— 权益曲线最大回撤
5. **夏普比** —— 日收益均值 / 标准差 × √252
6. **出场效率** —— 实际出场价相对 MFE 的捕获率
7. **（新增）数据真实度** —— 前端展示的数据中**实测来源**占比，禁止推算值冒充实测值。这是本规划的第一红线，见第 4 章。

### 0.4 明确不做的事（边界）

- **不做**投资建议与收益承诺。所有输出必须带 `disclaimer`（`strategy_lab.py` 已有先例）
- **不做**荐股营销、不做社区、不做付费内容
- **不接**真实券商通道**上线**，除非用户显式配置且通过实盘风控准入（`risk.py:342 live_switch` 已有准入闸门，保持默认关闭）
- **不做**高频/日内 tick 级策略。当前架构（`scheduler.py` 交易时段判定 + 分钟级扫描）定位在**日频到分钟级**

### 0.5 三年演进主线

```
2026 Q4  可信化       ── 数据真实度、指标正确性、模块边界清晰
2027 H1  可解释       ── 因子归因、信号溯源、AI 主脑个性化
2027 H2  可执行       ── 条件单/止盈止损、成本建模、真实成交语义
2028     可进化       ── 策略自动迭代闭环、跨市场联动建模
```

## 第 2 章 · 九大模块：目标与实现范围

### M1 · 计算能力与核心策略指标

**目标**：让"系统算出来的数"可信 —— 指标定义明确、口径一致、可复现、无前视偏差。

**实现范围（做）**
1. 修复 `quant_core.py` 指标名绑定（`_ta_sma`/`_ta_ema`/`_ta_macd`/`_ta_rsi`/`_ta_bb`/`_ta_atr`），恢复回测链路可运行
2. 建立**指标口径注册表** `server/indicators.py`：每个指标登记 `名称 / 参数 / 公式 / 数据窗口要求 / 输出列名 / 单位`
3. 真正实现 `qlib_factor_engine` 声明的 6 个因子公式，或**如实降级**为 4 个并改名（不允许元数据写 6 个、实算 4 个）
4. **实算 IC/IR**：IC = 因子值与未来 N 日收益的截面相关系数时间序列；IR = mean(IC)/std(IC)
5. 修掉前视偏差：改为**逐期截面回测**，每期只用当期可见数据选股
6. 参数全部接线：`weights`、`selected_factor_ids`、`start_date/end_date` 真实生效
7. `stock_pool` 搜索从 O(N) 线性改为字典索引；`quant_core` 加行情缓存

**实现范围（不做）**：不引入 Qlib 完整框架、不引入 GPU、不做分钟级特征

**验收标准**
- `quant_core.make_stock_features` 合成数据冒烟通过，8 个关键列非全 NaN
- 因子回测返回的 IC/IR **可被独立复算**（给出因子值序列与收益序列，第三方能算出同一数）
- 同一配置连跑两次结果**完全一致**（可复现）
- `weights` 改动能真实改变回测结果（Δ 非零）

**验收结论（2026-10-16 回填）**：✅ **已验证** —— 核心指标链路复活（曾因指标名未绑定到模块级全局，导致整条 `/api/quant/run` 链路是死的）；冒烟测试 13 个关键列非全 NaN（`sma_10=18.163`、`rsi_14=40.108`、`macd=-0.190`、`atr_14=0.374`）；`strategies.py` 长度门槛越界修复。

### M2 · 市场指标分析与世界金融市场动态影响建模

**目标**：从"罗列全球行情"升级为"**量化外部市场对 A 股的传导关系**"。

**实现范围（做）**
1. 全球资产从 11 个扩到覆盖度可用的规模（补：纳指期货、费半 SOX、VIX、美债 10Y、美元指数 DXY、A50 期货、恒生科技、布伦特原油）
2. **领先滞后分析**：计算各外部市场相对 A 股的滞后相关系数（lag 0/1/2/3 交易日），输出"领先性排序"
3. **开盘缺口传导**：隔夜美股/亚太 → 次日沪深 300 开盘缺口的统计关系（相关性 + 命中率）
4. **风险偏好通道**：VIX / 美债 10Y / 美元指数 → A 股风险偏好代理（结合涨跌家数、成交额）
5. **影响打分卡**：每日输出一张"外部环境对 A 股的利好/利空/中性"打分卡，**每项打分附证据与权重**
6. 传导关系**每日滚动重估**并落盘，前端展示历史稳定度

**实现范围（不做）**：不做宏观因子择时模型、不做汇率对冲计算

**验收标准**
- 每个传导结论都能下钻到"用了哪段数据、算出什么系数、样本量多少"
- 相关系数滚动窗口可复算；样本不足时**明确标注"样本不足"**而非给数
- 前端明确区分"实测相关"与"经验判断"

**验收结论（2026-10-16 回填）**：✅ **已验证** —— 7 个外部因子（djia/ixic/ndx/spx/vix/hsi/hstech）；领先滞后实测美 lead=1（隔夜效应）、港 lead=0；样本 <30 → `insufficient_samples` 不给系数；VIX 走 heuristic 且历史样本足够时 measured 自动优先；恒生 lag0 相关独立复算 0.508560（接口 0.50856，|ε|=2.21e-07）。

### M3 · 板块覆盖范围与市场金融属性关联能力

**目标**：板块不只是"今天涨了多少"，而是**有属性、有关联、有资金真相**的一张网。

**实现范围（做）**
1. **立刻停止伪造**（G5）：`net_flow` 与 5/20/60 日涨跌幅必须来自实测接口，推算值一律标注 `estimated: true` 并且**前端不得计入排序/结论**
2. 板块属性补全：PE(TTM)、PB、总市值、换手率、成分股数、领涨股、**行业分类（申万一级/二级）**
3. **板块—个股映射表**落盘（`data/sector_map.json`）：板块 → 成分股清单，支持反查"某股属于哪些板块"
4. **多周期真实收益**：从日 K 聚合出 5/20/60 日板块收益，替代写死系数
5. **板块关联图谱**：基于成分股重叠度 + 历史收益相关性，构建板块间关联（用于识别"同涨同跌簇"）
6. 板块覆盖从 Top50 扩到全量申万一级 + 二级

**实现范围（不做）**：不做行业估值分位排名（可延后）、不做供应链上下游图谱（需外部数据，列入 P2）

**验收标准**
- 前端任意板块数据可点开看到 `source` + `updated_at`
- 关闭所有推算逻辑后，页面仍能正常展示（只是少几个字段），**不出现假数**
- `sector_map.json` 反查任意一只股票能返回其所属板块列表

**验收结论（2026-10-16 回填）**：✅ **已验证** —— 覆盖率 496 板块 / `level` 414·39·43 / 168 个关联簇；多周期收益独立复算 d5/d20/d60 **偏差 0.0000**；金融属性敏感度复算 |ε|=4.47e-07；`sector_map.json` 反查可用（含 5657 只股票反向索引）。

### M4 · 自动化交易中心：买卖执行 + 复盘 + 决策

**目标**：从"能跑通的模拟盘"升级为"**语义正确的模拟盘**" —— 成交要像真的，风险要拦得住，决策要有账可算。

**实现范围（做）**
1. **成交成本模型**（G9）：滑点（可配 bps）、佣金、印花税（卖出 0.05%）、过户费；成交价改为"现价 ± 滑点"
2. **涨跌停/停牌校验**：涨停买单、跌停卖单直接拒绝并记录原因
3. **T+1 约束**：当日买入不可卖出
4. **止盈能力**：补 `take_profit_pct` / 移动止盈（回撤 X% 触发），与现有止损对称
5. **手动下单 / 撤单**：新增 `POST /api/automation/orders`、`DELETE /api/automation/orders/{id}`
6. **条件单**：价格触发 / 时间触发两类，落库由 `SignalMonitor` 轮询触发
7. **订单状态机**：补 `partial` / `partial_canceled`，为将来真实通道预留
8. **决策质量评分**（G11）：在 `trade_reviews` 基础上，按"信号强度 vs 实际结果"给每次决策打分并归因
9. **交割单导入**：支持 CSV 导入历史成交（真实账户复盘的前提）
10. **买卖点 K 线标注**：在 K 线上标出每个信号的买/卖点与盈亏

**实现范围（不做）**：不实现真实券商通道（保持 `broker_adapter()` 可插拔但默认空）；不做算法单/拆单

**验收标准**
- 同一笔模拟交易，手续费+印花税+滑点合计与手算一致
- 涨停价买入被拒绝，日志含明确 `reason`
- 当日买入的持仓调卖单被拒绝
- 止盈单在价格触发时正确平仓（可用合成报价验证）
- 导入一份交割单后，复盘页能看到对应闭合交易与归因

**验收结论（2026-10-16 回填）**：✅ **已验证（已交付部分）** —— 成本模型净口径（`pnl_basis=net`）手算一致（**BUY total=10010.10、SELL net=9984.90**）；涨跌停/停牌/T+1 约束；`exit_reason` 四类（take_profit/trailing_stop/fixed_stop/signal）；`is_drill` 演练隔离；新增 `GET /api/review/round-trips`；止盈默认 0（关闭，能力保留但不静默启用）。

⏳ **交付中（2026-10-16 排期中，尚未落地）**：手动下单（`POST /api/automation/orders`）、撤单（`DELETE /api/automation/orders/{id}`）、条件单（价格/时间触发）、订单状态机 `partial` / `partial_canceled`、决策质量评分（对应 `G10` / `G11`）。**这些不计入"已验证"。**

### 4.1 实测现状（2026-10-14 19:12 实测，非推断）

**关键结论：数据源可达性本身是波动的。** 这意味着两件事：
1. **不能把"可达性"写进逻辑假设** —— 降级路径必须始终存在且正确
2. **恢复可达是最危险的时刻** —— 真数据回来时，如果响应里还混着旧的推算字段，绿标会让编造内容获得"实时"的可信外观（本项目的 `net_flow` 与多周期涨跌幅正是如此，见 §4.3）

### 4.2 被暴露的设计缺陷：静默降级 + 谎报来源

`server/stable_market_provider.py` 的三个取数方法在真实请求失败后，都会**返回一小组写死的样本数据**：

| 方法 | 兜底位置 | 编造内容 | 行级 source |
|---|---|---|---|
| `get_hot_stocks` | `:113-122` | 5 只股票，价格 124.50 / 38.60 / 215.50 / 1680.00 / 32.10，编造 `hot_score`、编造推荐理由文案 | `"系统快照"` |
| `get_lhb_data` | `:199-207` | 4 条龙虎榜，编造买卖额与席位（"中信证券北京呼家楼 + 3家机构专用席位"） | `"系统快照"` |
| `get_sector_ranking_data` | `:275-307` | 24 个板块，`chg` 全 = 1.85、`amount` 全 = 284 亿、`turnover` 全 = 3.45、`net_flow` 全 = 12.5 亿、`5日/20日/60日%` 全 = 4.5/8.2/15.6 | `"系统快照"` |

**行级 `source` 是诚实的（"系统快照"），但接口信封把它覆盖掉了：**

- `server/routers/market_data.py:135` 无条件返回 `"source": "东方财富行业板块实时行情"`
- 于是前端拿到的是 **24 个全同值的编造板块，却被标注为"东方财富实时行情"**

**这直接解释了此前"粒子图全部板块净流入都是 12.5 亿"之谜** —— 不是数据偏斜，是数据根本不存在，24 个板块全是同一个常量。当时我按"分布退化"处理（加退化检测 + 警示），方向是对的，但**真因在这里**：降级数据被伪装成实时数据流进了可视化。

### 4.3 另一类伪造：由真实数据推算出来的"伪真实"

即使东财恢复，下面这些仍是推算值冒充实测值：

| # | 位置 | 伪造内容 | 危害 |
|---|---|---|---|
| 1 | `stable_market_provider.py:242` | `net_flow = amt * (up/(up+dn+1) - 0.5) * 0.4` —— 用涨跌家数比推算"资金净流入" | 与真实资金流无因果关系，用户据此判断资金方向会得出错误结论 |
| 2 | `stable_market_provider.py:262-264` | `"5日%": chg*1.85`、`"20日%": chg*3.42`、`"60日%": chg*5.80` —— 当日涨幅乘写死系数 | 用户以为看到多周期表现，实际是同一天涨幅的放大 |
| 3 | `qlib_factor_engine.py:331/352` | `combined_ic = 动量分均值×0.15`、`IR = IC×18` | IC/IR 是因子研究核心指标，编造会误导策略判断 |

### 4.4 处理原则（三条硬规则）

1. **实测优先**：能用真实接口取到的，绝不用推算
2. **降级必须可见**：任何 fallback 数据必须带 `synthetic: true` + `degraded: true`，**接口信封的 `source` 必须反映真实来源**，前端必须显示醒目横幅
3. **取不到就说取不到**：返回 `null` + `reason`，前端显示"暂不可用"，**不允许用假数填充**，更不允许把假数标注成真实数据源

### 4.5 正面范例（应作为全项目模板）

- `server/global_assets.py` → `coverage={available:0,total:11}` + `degraded:true` + 逐项 `available:false` + `price:null`：**降级如实上报，绝不填充**
- `server/ak_market.py:113 get_north_flow` → 返回 `disclosed` 标记（北向净买额自 2024-08 起已停止实时披露）：**如实说明"停止披露"**
- `server/stable_market_provider.py` 的**四级降级链**（已实现）：成功即原子落盘 → 失败时回放最近一次真实数据并标 `stale` → 东财不可达时用**腾讯通道成分股聚合**（标 `aggregated`）→ 只有连缓存都没有才用本地样本。这是比"全局降级到硬编码"高一个档次的做法。

### 4.5.1 已落地的降级链（实现细节）

**四级降级链**（板块排行 / 热门股 / 龙虎榜等处共用同一套实现）：

| 级别 | 触发条件 | 返回内容 | 信封 | 行级标记 |
|---|---|---|---|---|
| ① 真实直采 | 东财 push2 可用 | 实测数据 | `degraded: false`，真实来源名 | `synthetic: false`, `stale: false` |
| ② 历史快照回放 | 网络失败，**有盘缓存** | 最近一次真实数据 | `degraded: true`，`来源（历史快照 YYYY-MM-DD HH:MM）` | `synthetic: false`, `stale: true`, `stale_from` |
| ③ 腾讯通道聚合 | 东财 push2 不可达、**腾讯成分股可达** | 由腾讯成分股行情聚合出的真实板块指标（成交额加权涨跌幅 / 成交额求和 / 涨跌家数） | `degraded: true`，来源标注腾讯聚合 | `synthetic: false`, `aggregated: true`；`net_flow` 如实返回 `null`（不推算） |
| ④ 本地样本 | 网络失败且**无盘缓存** | 硬编码样本 | `degraded: true`，`系统快照（本地样本，非实时行情）` | `synthetic: true` |

> ⚠️ 第 ③ 级（腾讯聚合）与第 ① 级（东财直采）**口径不同**，**不可与①混用或横向对比**。

- 落盘为**原子写**：写 `.tmp<pid>` → `flush + fsync` → `os.replace`；任一步失败只记 warning，不污染已有缓存
- 缓存命中时 `logger.info` 记录使用了哪份缓存、哪个 `fetch_ts`，便于事后追溯
- 前端横幅按 `历史快照` 二分文案，直接显示真实时间戳

**关键性质**：④ 只在"首次部署 / 缓存被删"时出现，而不是每次网络抖动都出现。此前 push2 一断就整屏编造常量的问题由此根除。

### 4.6 数据源可达性加固（P0 工程项）

1. 东财取数从**单一明文 HTTP 节点**改为 **HTTPS 多节点轮询**（`push2` / `82.push2` / `90.push2`），补 `User-Agent` / `Referer` 请求头，超时 6s

3. **降级状态落盘并暴露**：新增 `GET /api/health/datasources` 返回每个通道的 `last_success_ts` / `last_error` / `consecutive_failures`
