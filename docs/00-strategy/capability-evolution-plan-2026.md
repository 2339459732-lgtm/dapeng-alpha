- 复盘结论 → 策略调整**没有自动化通路**（目前靠人看复盘 Tab 后手动操作）；

- 策略只有 2 个，因子与数据源单薄，**决策多样性不足**；
- 技术指标纯手写，未与成熟开源实现做**交叉校验**。

## 一、自动化模拟盘交易机制设计

### 1.1 闭环总览

```
┌─────────┐   信号    ┌─────────┐   订单   ┌─────────┐   成交/持仓  ┌─────────┐
│ 扫描层  │ ───────→ │ 执行层  │ ──────→ │ 账户层  │ ─────────→ │ 评估层  │
│ monitor │          │ gateway │         │  paper  │            │ review  │
└─────────┘          └─────────┘         └─────────┘            └────┬────┘
     ↑                                                                │
     │            ┌─────────┐      晋级/调参/降级       ┌─────────┐   │
     └─────────── │ 策略配置 │ ←────────────────────── │ 迭代层  │ ←─┘
                  │ (KV+DB) │                          │ (新建)  │
                  └─────────┘                          └─────────┘
```

- **扫描层（已有）**：`monitor._scan_round()` 在交易时段按固定间隔跑启用策略，生成信号；信号冷却防止重复触发；连续异常自动退避。
- **执行层（已有）**：`gateway` 校验门闸状态与风控规则后，将信号转为模拟订单。
- **账户层（已有）**：`paper` 撮合成交、维护持仓与现金；每日收盘由 `review` 幂等落一条权益快照。
- **评估层（已有）**：`/api/review/summary|equity|weekly` 输出北极星指标与周度中文叙述报告。
- **迭代层（待建，本规划核心）**：读取评估结果，按**决策矩阵**自动执行"晋级 / 保持 / 调参 / 降级 / 退役"，并把每一次决策写入 `audit_log`。

### 1.2 迭代层：复盘结果如何驱动策略优化

#### (a) 迭代触发器（何时启动一次迭代）

| 触发器 | 频率 | 说明 |
|---|---|---|
| 周度例行 | 每周五收盘后 | 复盘周报生成后自动跑一轮决策矩阵 |
| 阈值告警 | 实时 | 单策略浮亏 >8%、或连续 5 笔信号无成交、或回撤超阈值 → 即时触发 |
| 样本达标 | 事件驱动 | 策略闭合交易数 ≥5 笔（首次可统计）及之后每 +10 笔 |
| 门闸到期 | 事件驱动 | `paper_validating` 满 20 个交易日必须给出结论（晋级或退回） |

#### (b) 决策矩阵（指标组合 → 动作）

对**每个策略**独立评估（指标来自回测 + 模拟实盘两条线，模拟线权重更高）：

| 情形 | 判定条件 | 自动动作 |
|---|---|---|
| ✅ 晋级 | 模拟 ≥20 交易日 且 ≥5 笔闭合交易 且 胜率≥55% 且 盈亏比≥1.5 且 策略级回撤≤10% | `paper_validating→paper_passed`，审计记录 |
| ⏸ 保持观察 | 样本不足（<20 天或 <5 笔）但无恶化信号 | 不动作，周报中标注"累积中" |
| 🔧 触发调参 | 样本充足但胜率 45–55% 或盈亏比 1.2–1.5（"差一点达标"） | 生成**一个**参数微调提案（见 §1.3），进入回测队列 |
| ⬇ 降级 | 胜率 <45% 或盈亏比 <1.2 或策略回撤 >10% | `→draft` 并停用，强制重新走完整门闸流程 |
| 🗑 退役候选 | 连续两轮周度迭代均被降级，或 60 天零信号 | 标记 `retired_candidate`，周报中提请人工确认 |

> **原则：自动降级保守、自动晋级严格、调参只提案不生效。** 任何参数变更仍走"回退 draft → 回测 → 模拟验证"的完整门闸，与现有"改参数强制回退 draft"保护一致——自动化不绕过门禁，只加速流转。

#### (c) 防过拟合纪律（策略迭代的"交通规则"）

1. **样本外验证**：任何参数提案必须在**最近 20% 样本外数据**上复测通过才可进入模拟验证（Phase 2 落地 walk-forward 后升级为滚动样本外）。
2. **单变量原则**：一轮迭代只改一个参数维度（如只调均线周期或只调 ATR 倍数），禁止多维同时跳变——否则无法归因。
3. **改动幅度限制**：单次调整不超过原值 ±30%，避免参数空间乱跳。
4. **历史留档**：每组参数的回测指标、模拟指标、晋级/降级记录全部入 `audit_log`，形成策略的"版本谱系"，可回答"这个参数为什么是现在这个值"。
5. **不追短期噪声**：触发调参的最低样本是 5 笔闭合交易；周度波动不触发任何参数变更，只触发"观察"标注。

### 1.3 参数调优流程（单次迭代的标准动作）

```
复盘指标未达标
   ↓
生成参数提案（单变量、±30% 以内）
   ↓
回测队列执行：全样本回测 + 样本外复测
   ↓
两条线都优于现参数？──否──→ 放弃提案，保留现参数，记录"已探索"
   ↓ 是
参数写入配置（gate_state 自动回退 draft）
   ↓
回测通过 → backtested → 启用模拟 → paper_validating（重新累积 20 天）
   ↓
决策矩阵复评 → 晋级 / 再迭代
```

### 1.4 实验治理

- **策略超市化**（roadmap P1，与本规划 Phase 1 合并推进）：每策略一张卡片展示门闸状态、回测指标、模拟指标、当前版本谱系——迭代层的操作入口。
- **并发上限**：同时处于 `paper_validating` 的策略 ≤3 个，避免信号互相干扰导致归因困难。
- **人工否决权**：迭代层的所有自动动作都可在自动化面板一键撤销（撤销也入审计）。

## 二、GitHub 开源项目筛选与融合规划

### 2.1 筛选标准（五把尺子）

| # | 标准 | 要求 | 一票否决项 |
|---|---|---|---|
| 1 | 许可证 | MIT / BSD / Apache-2.0 可商用 | GPL 系（传染性强） |
| 2 | 维护活跃度 | 近 12 个月有提交，issue 响应正常 | 已归档/停更 >2 年 |
| 3 | 依赖成本 | 可**选择性引入**，不绑架本项目依赖树 | 强制拖入重型依赖（如 vn.py 的 C++ 交易网关全家桶） |
| 4 | 架构契合 | 能塞进现有 FastAPI + SQLite + 零新增重依赖的体系 | 要求替换整体架构 |
| 5 | 可剥离性 | 引入后如需移除，改动 ≤1 个适配层文件 | 代码侵入核心业务逻辑 |

### 2.2 候选项目评估与融合方式

融合分三档：**A 直接引入**（作为 optional dependency）、**B 借鉴重写**（吸收思路、按本项目约束重写）、**C 对标校验**（不引入代码，用其输出做正确性基准）。

| 项目 | 定位 | 评估 | 融合方式 | 优先级 |
|---|---|---|---|---|
| **akshare** | A 股/宏观数据源 | MIT、活跃、纯 Python；可补分红、财务、板块数据 | **A**：Phase 3 作为可选数据源适配层，失败时回退现有腾讯/百度源 | ★★★ |
| **pandas-ta** | 技术指标库 | MIT、纯 pandas、百种指标 | **C 为主**：先用于交叉校验现有手写指标（MA/ATR/突破）的数值正确性；差异 >0.5% 时以 TA-Lib 复核 | ★★★ |
| **TA-Lib** | 指标事实标准 | BSD、C 核心需编译，Windows 安装重 | **C**：仅在指标校验出现分歧时临时引入复核，不进主依赖 | ★★ |
| **vectorbt** | 向量化回测 | Apache-2.0、活跃、NumPy 向量化思路 | **B**：不重引其框架，吸收"向量化信号→成交矩阵"思路改造 `backtest.py`，支撑参数网格搜索性能 | ★★★ |
| **backtrader** | 回测框架 | GPL ❌、且已停更 | 不引入。仅读文档借鉴其**多数据馈送与滑点模型**概念 | ★ |
| **qlib (Microsoft)** | AI 量化平台 | MIT、活跃但重（依赖 LightGBM 等） | **B**：Phase 4 借鉴其**因子库组织方式与 IC/RankIC 评估方法**，重写轻量版因子评估模块 | ★★ |
| **vn.py** | 实盘交易框架 | MIT、活跃、但体量巨大且面向实盘网关 | 不引入整体。**B**：借鉴其**事件引擎与网关抽象**，为将来（若）接实盘预留接口形态 | ★ |
| **pytdx / mootdx** | 通达信行情 | 与本项目现有腾讯/百度源重复 | 仅作为行情源断流兜底候选，暂不引入 | ★ |

### 2.3 引入流程（每个项目过五道门）

```
评估（按 §2.1 打分，写入本文件附录） → 隔离（全部封装在 server/vendor/<name>/ 适配层）
→ 灰度（先只在回测/校验路径启用，不碰交易主链路） → 双跑对比（与现有实现并行 ≥2 周）
→ 决策记录（采纳/放弃及理由入 audit_log 与本文档）
```

> **红线**：任何开源组件不得直接出现在 `server/trading/` 交易主链路里，必须隔着适配层；引入失败时拔掉适配层即恢复原状。

## 三、分阶段路线图

### Phase 0 —— 基线（已完成 ✅，2026-10-07）

- **目标**：打通"扫描→模拟→评估"链路与北极星度量。
- **关键任务**：门闸状态机、模拟账户、回测引擎、2 个内置策略、复盘系统（北极星指标 + 权益曲线 + 周报）、DeepSeek 通电。
- **衡量指标**：3 个复盘 API 全通；复盘 Tab 桌面/移动端零报错；4 只验证股票 AI 研判实时返回。

### Phase 1 —— 自动化闭环补全（2026 Q4，约 6–8 周）

- **目标**：迭代层落地，系统第一次实现"自己复盘、自己调参提案、自己晋级/降级"，人工只做确认。
- **关键任务**：
  1. 实现迭代层引擎：决策矩阵（§1.2b）+ 四类触发器（§1.2a），全部动作入 `audit_log`；
  2. 周度迭代 Job：周五收盘周报生成后自动跑一轮，结果推送到复盘 Tab 新增"迭代记录"卡片；
  3. 策略超市化卡片（roadmap P1 合流）：门闸状态、双轨指标、版本谱系、一键撤销；
  4. 阈值告警通路复用现有邮件通知（QQ SMTP，待用户提供授权码）；
  5. 补充策略至 4–5 个（均值回归、量价背离各一），让决策矩阵有真实对比对象。
- **衡量指标**：
  - 迭代动作 100% 有审计记录，且无一绕过门闸（抽查 `audit_log`）；
  - 至少 1 个策略走完"调参提案→样本外复测→重新模拟验证"全流程；
  - `paper_validating→paper_passed` 首次由**自动晋级**（而非手动 confirm）完成；
  - 周报连续 8 周不中断（复盘系统已有 streak 指标直接沿用）。

### Phase 2 —— 回测与评估增强（2027 Q1，约 6 周）

- **目标**：把回测从"单次全样本"升级为"可抗过拟合、可批量搜索"的工业级评估。
- **关键任务**：
  1. **walk-forward 验证**：滚动窗口（如 250 日训练 / 60 日样本外），输出 OOS 指标，接入迭代层决策矩阵替代单一回测指标；
  2. 回测引擎向量化改造（借鉴 vectorbt 思路，方式 B），参数网格 100 组回测从分钟级降到秒级；
  3. 指标交叉校验：用 pandas-ta（方式 C）比对全部手写指标，差异报告归档；
  4. 回测真实性增强：滑点 + 手续费模型（读 backtrader 文档提炼）、涨跌停不可成交规则；
  5. 策略级归因报表：每笔模拟成交可回溯到信号 K 线上下文（复盘页点击订单看当时图表）。
- **衡量指标**：
  - 所有启用策略均有 OOS 指标，且晋级判定必须引用 OOS（防过拟合硬约束生效）；
  - 手写指标与 pandas-ta 数值偏差全部 <0.5%（或有书面解释）；
  - 100 组参数网格回测耗时 <10 秒；
  - 模拟成交回溯覆盖率 100%（订单 ↔ 信号 ↔ K 线上下文三链齐全）。

### Phase 3 —— 数据与因子能力（2027 Q2，约 8 周）

- **目标**：从"纯价量"扩展到"价量 + 基本面 + 市场宽度"的多维分析，支撑更丰富的策略假设。
- **关键任务**：
  1. akshare 适配层（方式 A）：财务、分红、板块成分、北向资金；断流自动回退现有源；
  2. 轻量因子库（借鉴 qlib 组织方式，方式 B）：因子定义 / 计算 / IC 评估三件套，首批 10–15 个因子（动量、波动、量价、估值、质量）；
  3. 因子有效性看板：IC / RankIC / 分层收益，纳入复盘 Tab；
  4. 市场宽度模块：涨跌家数、新高新低、行业轮动强度，作为策略的"环境过滤器"（大盘环境差时自动降仓/停信号，复用 risk 模块通路）；
  5. 基于因子的第 5–6 号策略进入门闸流程。
- **衡量指标**：
  - 因子库 ≥10 个因子且全部有 IC 评估记录；
  - 环境过滤器上线后，大盘单边下跌段的模拟回撤较 Phase 2 基线**下降 ≥20%**；
  - akshare 源可用率 ≥95%（故障自动回退不中断服务）；
  - 至少 1 个因子策略进入 `paper_validating`。

### Phase 4 —— 决策智能升级（2027 Q3 起，持续）

- **目标**：AI 从"单票研判"升级为"组合视角 + 市场状态感知"的决策层。
- **关键任务**：
  1. 市场状态识别（regime detection：趋势/震荡/高波动三态），策略参数按状态自动切换预设档位；
  2. LLM 研判与量化信号的**集成决策**：DeepSeek 输出作为独立一票进入信号合成，分歧时降仓而非二选一；
  3. 组合层风控：行业集中度、相关性约束（风险敞口上限），从"单票风控"升到"账户风控"；
  4. 复盘系统 2.0：周报复盘加入"AI 自检"——LLM 读指标与审计日志，指出迭代层决策中的可疑模式（如频繁调参）；
  5. 北极星终审：2027 年底对照 2026-12-31 基线目标做年度验收。
- **衡量指标**：
  - 北极星指标持续达标：90 日滚动超额 ≥+3pct、maxDD ≤10% 且 ≤基准、胜率 ≥55%、盈亏比 ≥1.5、可追溯性 100%；
  - 市场状态识别回测标注准确率 ≥70%（人工抽样核对）；
  - AI 与量化信号分歧时的降仓动作 100% 有记录且可解释。

## 四、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 过拟合：迭代层把噪声当规律 | 策略样本内好看、实盘失效 | P2 walk-forward + OOS 硬约束；单变量、±30%、最小样本量三重纪律（§1.2c） |

| 开源引入拖垮架构 | 依赖膨胀、升级困难 | 五把尺子 + 适配层隔离 + 灰度双跑（§2.1/§2.3），GPL 一票否决 |
| 自动化误动作 | 错误晋级/降级 | 晋级严格、降级保守、调参只提案；一切可一键撤销且入审计（§1.4） |
| 行情源断流 | 扫描与复盘中断 | roadmap 既有项，P3 随 akshare 适配层一并做自动回退 |
