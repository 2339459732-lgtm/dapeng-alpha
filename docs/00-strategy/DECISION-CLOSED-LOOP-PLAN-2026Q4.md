## 0. 设计目标与原则

### 0.1 一句话目标

让一次交易判断能够完整回答五个问题：

1. 当时看到了什么（同一份 `MarketPacket`）；
2. 市场处于什么状态（动态调查）；
3. 市场体温是多少、由什么驱动（情绪六维）；
4. 不同视角的专家分别怎么判断、为什么冲突（主脑专家团）；
5. 最终为什么这样决策、什么条件会推翻它，事后结果如何校准（决策台与复盘）。

### 0.2 五条硬原则

| 原则 | 执行约束 |
|---|---|
| 单一事实源 | 一个决策周期只冻结一份 `MarketPacket`，所有模块共享 `trace_id / as_of / coverage / quality`，禁止各自拼接不同时间戳的数据 |
| 证据先于观点 | 每个判断绑定指标值、来源、样本量与失效条件；无源数字不得进入加权 |
| 风控优先 | 硬否决与仓位闸门高于多数意见；数据质量门槛高于模型自信 |
| 诚实降级 | 缺失返回 `null + reason`，按可用权重重归一；覆盖 < 70% 不输出可执行结论 |
| 闭环可学习 | 保存专家原始意见、分歧、决定和结果；T+1/T+3/T+5 回看后才允许调整权重 |

## 1. 动态市场调查

### 1.1 目标

把已有行情、板块、资金、全球联动、新闻与情报，整理为一份可追溯、可比较、可驱动决策的市场事实包 `SurveySnapshot`。调查不是资讯摘要，而是后续研判的事实底稿。

### 1.4 采集与更新频率

| 节拍 | 频率 / 窗口 | 执行内容 | 设计理由 |
|---|---|---|---|
| L0 行情快照 | 源缓存 60 秒；前端 60 秒刷新 | 指数、宽度、涨跌停、成交额、板块快照 | 对齐现有缓存，不向上游高频打点 |
| L1 动态调查 | 常规 15 分钟；压力态 5 分钟；闭市暂停 | `SurveySnapshot`、轮动、异动、总结 | 现状 30/15 分钟；逐步加密，闭市保留 15:05 日结 |
| L2 情绪采样 | 盘中 1 分钟原始值；5 分钟发布；15:05 定格 | 六维分、总分、覆盖度、背离 | 情绪必须比调查报告更及时 |
| L3 专家研判 | 快照实质变化触发，同一 trace 不重复 | 六专家独立研判、交叉复核、主脑汇总 | 以快照哈希幂等，避免重复 LLM 调用 |
| L4 全球/情报 | 全球 30-60 分钟；情报 30 分钟，盘后 60 分钟 | 外盘、风险等级、事件摘要 | 变化慢于 A 股盘面 |
| L5 日结 | 15:05 一次；每周一次汇总 | 冻结最终快照、写复盘、校准 | 让结果与当天决策一一对应 |

**事件触发条件**（任一成立则打破常规节拍）：

- 情绪分相对上一快照变化 ≥ 10 分，或状态跨档；
- 上证或创业板日内涨跌绝对值 ≥ 1%，或涨跌停净差变化 ≥ 20 家；
- 情报风险升至中/高，或数据源从不可用恢复；
- 用户手动刷新（生成新 `trace_id`，不复用旧结论）。

连续压力态最多 3 轮，之后回到常规节拍，防止异常状态自身形成流量风暴。

### 1.6 快照质量硬规则

1. 每个快照必须携带 `trace_id / as_of / generated_at / scope / coverage / source / quality`；
2. 多源冲突按「来源优先级 + 同一 as_of」对齐，无法对齐则标记 `conflict` 并剔除该字段，禁止取平均；
3. 关键字段缺失按缺失处理并重归一权重，**禁止用 0、50 或经验常数填坑**；
4. 快照超过 1 个交易日不得进入当日执行建议；历史数据必须显示 `stale=true` 与距今时长。
5. **口径必须自描述（2026-11-02 补充）**：`sentiment.v1` 输出 `data_scope`（`full_a_share` / `core_sample`）与 `scope_label`。全市场缓存未就绪时会回退 447 只核心样本，此时必须打 `scope_degraded` 标记；降级态 `MarketPacket` 只做 5 秒短缓存，避免重启后 55 秒内所有结论锁死在核心样本上。
6. **风险旗标按强度分级（2026-11-02 补充）**：涨跌停两端同时活跃时，仅当两侧接近均衡（`min/max ≥ 0.5`）才判 `high` 并称「结构撕裂」；一侧主导时降为 `medium` 并改称「分化加剧」，避免普涨日被误判为高风险。

## 2. 主脑研判机制

### 2.1 目标与现状差距

目标是把单次 LLM 汇总拆成六位独立专家：先独立判断，再匿名互评与交叉质询，最后由主脑按证据质量与历史校准汇总。讨论过程、意见冲突和少数意见全部留痕。

现状是单脑单次 `brain.py::_advise()`，没有专家输出结构、没有讨论、没有结果校准，因此无法回答「哪条证据导致哪个专家改变结论」。

### 2.2 六位研判专家

| 代号 | 专家 | 独立视角 | 必须回答的问题 | 否决 / 降级权 |
|---|---|---|---|---|
| E1 | 趋势与结构 | 指数趋势、均线结构、宽度、动量持续性 | 趋势延续、箱体还是结构破坏？失效位在哪里？ | 无硬否决 |
| E2 | 板块轮动 | 相对强弱、轮动阶段、领涨质量、题材集中度 | 主线能否延续？扩散、加速还是高位分歧？ | 无硬否决 |
| E3 | 资金与流动性 | 成交额、换手、资金流、北向结构 | 上涨是否有量承接？下跌是否出现流动性风险？ | 流动性硬否决，可压仓位到 0-30% |
| E4 | 全球与事件 | 外盘领先滞后、VIX/美元、宏观、地缘情报 | 外部冲击是否足以改变方向？脉冲还是持续？ | 重大事件硬否决 |
| E5 | 情绪与行为 | 情绪分、六维贡献、宽度背离、极端情绪 | 修复、过热还是衰竭？是否存在量价/宽度背离？ | 极端情绪可降为观察 |
| E6 | 反方与证据审计 | 反例、尾部风险、样本充分性、时间戳一致性 | 最强共识最可能错在哪里？什么证据能推翻它？ | 数据不足时强制输出观察 |

### 2.3 统一输出契约

```json
{
  "expert_id": "E3",
  "round": 1,
  "stance": "attack | neutral | defend",
  "horizon": "intraday | 1-3d | 1-2w",
  "confidence": 0.0,
  "thesis": "不超过 120 字，必须包含因果链",
  "evidence": [
    {"metric": "amount", "value": 4292.01, "unit": "亿元", "source": "market-dashboard", "as_of": "2026-11-01T15:00:00+08:00", "sample": 5540}
  ],
  "counter_evidence": ["至少一条反例；无法给出则说明盲区"],
  "invalidation": "触发即撤销本轮观点的阈值或事件",
  "position_cap": 0,
  "questions": ["只问能改变结论的问题，最多 3 条"],
  "data_quality": {"coverage": 0.93, "stale": false, "conflicts": []}
}
```

### 2.4 讨论与交叉验证流程

| 步骤 | 名称 | 规则 | 输出 | 状态 |
|---|---|---|---|---|
| S0 | 冻结快照 | 所有专家读取同一个 `MarketPacket`，禁止自行补数 | frozen packet | ✅ 已交付 |
| S1 | 独立研判 | 六位专家并行、互相不可见；先写结论，再列证据与反证 | 6 份 round=1 意见 | ✅ 已交付 |
| S2 | 匿名互评 | 隐藏身份（代号甲-己），仅展示观点/证据/置信度；改判必须引用新增证据；最多两轮 | 互评记录 | ✅ 已交付（规则 v2） |
| S3 | 交叉质询 | 主脑只追问分歧最大的 2-3 个问题；反方对最强共识做定向攻击 | challenge log | ✅ 已交付（E6 定向质询，≤4 条） |
| S4 | 主脑汇总 | 先执行风控否决和数据门槛，再按证据、校准、置信度加权 | BrainDecision | ✅ 已交付 |
| S5 | 发布留痕 | 同时写入决策台与档案，包含异议、分歧、失效条件 | audit record | ✅ 已交付（决策台流程条 + 逐人审阅） |
| S6 | 结果校准 | T+1/T+3/T+5 回看，每 20 个有效样本更新一次专家校准，单次 ≤ 0.10 | calibration update | ⏳ P2 |

**已实现的互评判定规则（`deliberate_expert_opinions`，确定性纯函数）：**

1. **冲突只在方向不同时成立**。`dir_self` 与同行加权方向 `peer_dir` 符号相反，或自己中性而 `|peer_dir| ≥ 0.20`，才算争点；同为进攻而强度不同属「认同」，不是分歧。早期版本用连续方向差值判定，会把强度差误报成对立，导致一致率恒为 0，已修复并有回归测试。
2. **修正门槛**：反对票信心之和须超过支持票之和的 **1.15 倍**（`_REVISE_CONF_GAP`）才迫使改判。改判后方向向同行均值靠拢，信心按证据差衰减，衰减上限 35%，并同步下调仓位上限。
3. **坚持**：支持信心不低于反对方时保留原判断，写入 `disputes`，由主脑按信心加权计入分歧指数，不允许被静默抹平。
4. **认同**：方向一致则信心 +0.03（上限 0.95），作为交叉验证成立的加成。
5. **E6 不参与打分**，只对「有反证却未自我修正」的专家发质询，问题直接取自该专家自己列出的 `counter_evidence`。
6. 全过程输出 `reviews / disputes / audit_queries / cross_validation.matrix / process`，同一份 round-1 意见必然得到同一份审阅结论（可复算）。

成本约束：最多两轮，六位专家 + 主脑一次汇总 ≤ 13 次模型调用；无 LLM 时使用六套规则模板保底，输出必须标记 `rule_v2_deliberated`（或 `rule_v1`），不得冒充 AI 结论。

### 2.5 汇总公式与决策阈值

```text
sᵢ ∈ {-1, 0, +1}       expert stance (defend / neutral / attack)
cᵢ ∈ [0, 1]            expert confidence
kᵢ ∈ [0.5, 1.0]        historical calibration
wᵢ                      role weight (normalized)
C = Σ(wᵢ·kᵢ·cᵢ·sᵢ) / Σ(wᵢ·kᵢ·cᵢ)
D = 1 - |C|            disagreement index
Confidence = mean(cᵢ) × (1 - 0.4D) × Q
Q = data quality coefficient (0-1)
```

| 判定条件 | 结论 | 执行约束 |
|---|---|---|
| `C ≥ +0.25` 且无否决 | 进攻 | 仓位上限 = min(专家建议, 风控闸门) |
| `-0.25 < C < +0.25` | 均衡 / 观察 | 不为了给答案而选方向，给出触发条件 |
| `C ≤ -0.25` 或存在否决 | 防守 | 仓位上限取最低值；重大事件可降为 0 |
| `Q < 0.70` 或关键数据缺失 | 无结论 | 只输出缺口与补数计划 |
| `D > 0.55` 且双方置信度 ≥ 0.70 | 重大分歧 | 标记不建议执行，等待新快照或裁决证据 |

### 2.6 意见冲突处理

| 冲突 | 处理 |
|---|---|
| 方向冲突 | 按校准权重计算 C，不按人数简单多数；落入中性区就观察，不强行裁决 |
| 风控否决 | 硬否决优先于加权分，仓位取最低值，主脑无权覆盖 |
| 证据冲突 | 同一指标不同来源先对齐 as_of；无法对齐则剔除并标记 conflict，交 E6 审计 |
| 数据不足 | 相关专家弃权，剩余权重归一；覆盖 < 70% 禁止输出进攻仓位 |
| 锚定 / 从众 | 第二轮无新增证据的改判无效，保留原意见并在审计中标记 |
| 成本收益冲突 | 短线机会强但风险收益比不足时，由仓位闸门约束，不追价 |

### 2.7 决策依据优先级

1. **事实完整性**：快照覆盖、时效、来源一致性未过门槛，任何专家都不得给可执行结论；
2. **风险约束**：硬否决和仓位闸门先于方向判断；
3. **可验证证据**：有来源、有时间、有样本的证据优先于叙述；
4. **历史校准**：长期表现更稳定的专家权重更高，但单次结果不立即大幅调权；
5. **保留异议**：最终结论必须附带反方意见和失效条件，复盘时区分判断错误、执行偏差与数据缺失。

## 3. 市场情绪追踪

### 3.1 采样范围与口径

- **样本**：系统覆盖的沪深 A 股样本，不含 ETF / 港股；不代表交易所全市场。
- **输入**：指数、涨跌家数、涨跌停、成交额与换手、板块集中度、全球联动、新闻与情报。
- **输出**：`SentimentSnapshot`，包含总分、六维贡献、覆盖度、置信度、风险旗标、版本号、`as_of`。
- **禁止**：调用外部“投资者情绪调查”冒充本系统实测；北向净买额停止披露后不得推算。

### 3.2 六维量化

| 维度 | 采集指标 | 公式（0-100） | 权重 | 状态 |
|---|---|---|---|---|
| 宽度 B | 上涨/下跌/平盘、中位涨跌 | `100 × up ÷ (up + down)` | 30% | 已具备 |
| 动量 M | 三大指数平均涨跌；MA20 上方占比 | `clamp(50 + 25×avg_chg + 0.3×above_ma20_pct, 0, 100)` | 20% | 指数已具备，MA20 需补 |
| 涨跌停 L | 涨停、跌停家数 | `clamp(50 + 40×(lu-ld)/(lu+ld+5), 0, 100)` | 15% | 已具备，连板待补 |
| 量能 V | 成交额优先；不足时用沪/深综指日成交量 | 当日值相对过去 20 个交易日百分位 × 100；盘中按 U 型时段曲线折算全天预估并标 `estimated:true` | 15% | 已交付；成交额样本满 20 日后自动接管 |
| 全球 G | 全球联动 composite | `clamp(50 + 12×composite, 0, 100)` | 10% | 已具备 |
| 事件 E | 情报风险分、正负面新闻占比 | `clamp(50 - 0.25×risk - 50×neg + 50×pos, 0, 100)` | 10% | 规划；先用关键词规则并标 heuristic |

```text
S = 0.30B + 0.20M + 0.15L + 0.15V + 0.10G + 0.10E
```

**缺失与可信度**：缺失维度不补 50 分，按剩余可用权重重新归一；`coverage = 可用权重之和`，低于 70% 总分返回 `null`，不许用中性分掩盖。置信度 = coverage × 数据质量 × 样本稳定度，分高/中/低三档。

### 3.3 状态档位

| 区间 | 状态 | 含义 | 视觉 |
|---|---|---|---|
| 0-20 | 极冷 | 恐慌 / 流动性收缩 | 绿 |
| 20-40 | 偏冷 | 风险偏好低，等待修复 | 浅绿 |
| 40-60 | 中性 | 多空平衡，重结构轻方向 | 灰/金 |
| 60-80 | 偏热 | 风险偏好回升，注意拥挤 | 橙红 |
| 80-100 | 过热 | 情绪拥挤，防冲高回落 | 红 |

### 3.4 独立风险旗标

1. 价格与宽度背离：指数涨但上涨家数 < 40%；
2. 量价背离：指数涨但成交额处于近 20 日低分位；
3. 结构性撕裂：涨停与跌停同时高于近 20 日 80 分位；
4. 拥挤交易：前 3 板块成交额集中度显著抬升；
5. 事件冲击：情报风险中/高时，情绪分虽高也降低可信度与仓位。

### 3.5 展示形式

| 区域 | 内容 | 交互 |
|---|---|---|
| 顶部总览 | 情绪仪表、档位、置信度、覆盖度、as_of | 点击查看公式与来源 |
| 六维分解 | B/M/L/V/G/E 贡献条与权重 | 下钻原始指标与时间 |
| 历史轨迹 | 1/5/20 日曲线 + 状态带 + 跨档标记 | 切换周期、对比事件 |
| 结构体温 | 涨跌阶梯、涨跌停温度计、板块热力 | 点击进入板块详情 |
| 风险旗标 | 背离、极端分歧、拥挤、事件风险 | 关联调查与决策记录 |
| 证据抽屉 | 公式、输入值、来源、覆盖率、版本 | 复制 trace_id |

原始指标 1 分钟采样，情绪分 5 分钟发布，15:05 定格为当日最终值；历史只追加不覆盖。

## 4. 三系统闭环

### 4.1 数据流

```text
┌──────────────── 数据源（腾讯 / 新浪 / 东财 / AkShare / 情报）────────────────┐
│                                                                              │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
                   SnapshotHub（质量门禁 + trace_id）
                                │  MarketPacket（只读）
              ┌─────────────────┼──────────────────┐
              ▼                 ▼                  ▼
      动态市场调查         市场情绪追踪         决策台（当前事实）
      SurveySnapshot      SentimentSnapshot           │
              │                 │                      │
              └────────┬────────┘                      │
                       ▼                               │
              主脑六专家独立研判 + 互评                │
                       │                               │
                 BrainDecision ────────────────────────┘
                       │
              DecisionMemo（方向/仓位/触发/止损/异议）
                       │
             纸面执行 / 用户计划 / 复盘
                       │
              CalibrationUpdate（T+1 / T+3 / T+5）
                       │
        ┌──────────────┴───────────────┐
        ▼                              ▼
  专家校准系数                   情绪权重 / 调查阈值
        └──────────────► 下一轮快照（不改历史）
```

**防循环规则**：同一轮里，调查先生成宽度/板块基线；情绪读取该基线但不等待调查的 AI 总结；主脑读取两份已冻结快照；决策台只读主脑结论。下一轮情绪可使用上一轮调查的 regime，但不反向覆盖本轮结果。

### 4.2 模块输入 / 输出 / 依赖

| 模块 | 输入 | 输出 | 下游 | 依赖类型 | 断链处理 |
|---|---|---|---|---|---|
| SnapshotHub | 行情、板块、资金、全球、新闻、宏观、情报 | `MarketPacket` | 调查、情绪、主脑、决策台 | 硬依赖（底座） | last-good + 质量降级 |
| 动态调查 | `MarketPacket` + 宏观/新闻/情报 + 历史 | `SurveySnapshot` | 情绪基线、主脑、决策台 | 硬依赖市场，软依赖情报 | 输出观察版，不编数 |
| 情绪追踪 | `MarketPacket` + 宽度/板块 + 全球 + 新闻 | `SentimentSnapshot` | 主脑 E5、决策台、下轮调查 | 硬依赖宽度，软依赖全球/新闻 | 缺失维度重归一，<70% 无分 |
| 主脑专家团 | 两份快照 + 记忆 + 组合/风控 | `BrainDecision` | 决策台、复盘 | 硬依赖两份快照 | LLM 失败走规则专家；数据不足审计否决 |
| 决策台 | `BrainDecision` + 持仓 + 风控 | `DecisionMemo` | 用户、模拟执行、复盘 | 硬依赖主脑 + 风控 | 显示无结论，不默认方向 |
| 复盘校准 | 成交、`DecisionMemo`、后续行情 | 结果标签、校准系数、失败经验 | 专家权重、情绪权重、调查阈值 | 软依赖（学习层） | 样本不足保持默认权重 |

### 4.3 共享契约

每条记录必须包含：

- `trace_id`：贯穿快照、调查、情绪、专家、决策、复盘的唯一键；
- `as_of / generated_at`：观察时间与生成时间分离；
- `scope / coverage / quality`：样本范围、覆盖率、质量等级；
- `source / stale / conflict`：来源、快照状态、冲突字段；
- `evidence[]`：指标、数值、单位、来源、时间、样本量；
- `version`：数据契约、情绪公式、专家提示词版本。

### 4.4 升级优先级

| 优先级 | 升级项 | 覆盖 | 完成判定 |
|---|---|---|---|
| P0 | 统一 `MarketPacket` + 质量门禁 + `trace_id` | 底座 / 三系统 | 同一周期三模块 trace_id 一致，缺失字段不补 0 |
| P0 | `sentiment.v1` + 六维输入 + coverage | 情绪 / 调查 / 决策 | 同一输入复算误差 ≤ 1e-6 |
| P0 | 六专家独立意见 + 主脑汇总 + 冲突处理 | 主脑 / 决策台 | 每次 BrainDecision 有 6 份意见、C/D、否决、失效条件 |
| P0 | 三系统共享读模型 + 决策台证据链 | 全链路 | 可从结论下钻调查、情绪、专家；断源不空白 |
| P1 | 匿名互评两轮 + 反方质询 + 讨论时间线 | 主脑 / 决策台 | D > 0.55 时不强行进攻 |
| P1 | 情绪历史 + 量能分位 + 趋势图 | 情绪 | 连续 20 日可重放，手工复算一致（量能维已交付，成交额口径待累积满 20 日） |
| P1 | 专家校准 + 决策结果回写 | 主脑 / 复盘 | 每 20 个样本更新，单次 ≤ 0.10 |
| P2 | 事件驱动调频 + 源恢复重算 + 告警 | 调查 / 情绪 | 触发/抑制/恢复有审计日志 |
| P2 | 新闻情绪分类 / 学习权重 / 多周期专家 | 情绪 / 主脑 | 启发式与实测可区分，回测有增益才启用 |

### 4.5 验收标准

1. 一次决策可完整还原：快照 → 调查 → 情绪 → 六专家 → 讨论 → 主脑 → 决策卡 → 复盘；
2. 任一数据源断开，其余模块仍显示最近成功快照与降级原因，不出现 0.00、50 分或“中性”冒充真实值；
3. 情绪分可由已存原始输入独立复算；专家方向可由证据表复核；最终仓位不超过风控闸门与专家最低上限；
4. 每条结论附「什么会改变判断」，复盘能区分方向错误、执行偏差与数据缺失。

### 4.6 明确不做

- 不接自动实盘下单；
- 不追求每次都给方向，无优势时输出观察是合法结果；
- 不让 LLM 补数、改数或绕过风控；
- 不把新增高频数据源作为前置条件，先用现有可验证数据把口径与闭环做对。

## 6. 系统架构与数据治理（2026-11-02 升级）

> 本节回答四个问题：数据怎么流、谁来刷、什么时候失效、面板是否同一时点。
> 对应实现：`server/data_bus.py`、`server/market_scanner.py`、`server/cache.py`。

### 6.1 分层架构

| 层级 | 职责 | 核心模块 | 输出 |
|---|---|---|---|
| L0 采集层 | 拉取并校验外部数据；缺失返回 `null + reason`，禁止推算 | `market_coverage`（新浪全 A / 东财基本面 / 腾讯全球 / US Treasury·NY Fed·ECB / World Bank） | 报价、季度基本面、全球指数、宏观指标 |
| L1 派生层 | 只消费已加载快照，派生结构指标，不新增重量级抓取 | `market_scanner`（cross_section / rotation / money_flow） | 横截面结构、板块轮动、资金流向 |
| L2 快照层 | 冻结同一时点市场事实，跨模块单一事实源 | `decision_snapshot.get_market_packet` | MarketPacket（trace_id / as_of / quality / evidence / chain） |
| L3 情绪层 | 六维情绪；缺失维度按剩余权重重归一 | `decision_snapshot.build_sentiment_snapshot` | sentiment.v1 |
| L4 研判层 | 六专家独立研判 → 匿名互评 → 联合研判 → 命中账本 | `decision_experts` | brain-panel.v3 |
| L5 呈现层 | 结论优先的 17 卡决策台，SSE 实时同步 | `decision-desk.js` / `dashboard.html` | 决策台界面 |
| L6 治理层 | 资源依赖图、级联失效、事件推送、缓存容量治理 | `data_bus` / `cache` / 观测路由 | `/api/decision/bus · cache · system` |

### 6.2 模块职责边界

| 模块 | 只做什么 | 不做什么 |
|---|---|---|
| `market_coverage.py` | 采集、校验、分级 TTL、后台刷新 | 不做派生分析、不做情绪与研判 |
| `market_scanner.py` | 从快照派生横截面/轮动/资金流 | 不打额外上游、不写结论 |
| `decision_snapshot.py` | 组装 MarketPacket、计算情绪、量能回填 | 不判断方向、不给仓位 |
| `decision_experts.py` | 六专家意见、互评、联合研判、命中账本 | 不直接下单、不改历史结论 |
| `data_bus.py` | 资源注册、依赖、级联失效、事件推送 | 不存数据（缓存仍在 TTLCache） |
| `cache.py` | 存取、TTL/LRU/字节淘汰、回收、统计 | 不理解业务语义 |
| `routers/decision.py` | API 编排、SSE 协议 | 不写业务规则 |

### 6.3 数据更新触发机制

| 触发类型 | 触发条件 | 作用范围 | 节拍 / 闸门 |
|---|---|---|---|
| 时间触发 | 后台 worker 到点 | coverage 全量刷新 | 交易 120s / 非交易 1800s，失败退避 |
| 事件触发 | coverage 刷新成功 | 失效 packet | 闸门 60s |
| 事件触发 | packet 重建完成 | 失效 sentiment / scan | 闸门 40s（快照 TTL 55s） |
| 事件触发 | sentiment / scan 刷新 | 失效 experts | 闸门 180s（专家团重算最重） |
| 请求触发 | HTTP 读取且过期 | 单资源重建 | TTL 55 / 45 / 120 / 300s，single-flight |
| 手动触发 | `?refresh=1` | 单资源强制刷新 | 立即，仍受上游退避约束 |
| 订阅推送 | 任意资源发布事件 | SSE 客户端 | 事件驱动 + 30s 心跳 |

设计取舍：级联采用「发布者自身失效节拍」而非下游 TTL 判断，保证**首次刷新必级联、后续按闸门收敛**；
闸门过小会把专家团打成重算风暴（每次含互评与账本落盘），过大则面板时点漂移，180s 为实测折中。

### 6.4 缓存与保留策略

| 策略 | 参数 | 行为 |
|---|---|---|
| 双上限 | 800 条 / 64MB | 任一超限：先回收过期 → 再 LRU 淘汰，直到回到预算内 |
| 单条拒写 | 单条 > 64MB | 拒写并计 `oversize_rejected`，防止单对象清空缓存 |
| 分级 TTL | packet 55s、sentiment 45s、scan 120s、coverage/experts 300s | 按数据变化速度分层，避免「一刀切 TTL」 |
| 后台回收 | 30s | 与写入解耦，夜间无写入也会清理过期条目 |
| 历史文件 | sector_history 40 日、expert_ledger 120 日、sentiment series 上限 | 临时文件 + 原子替换，避免半写损坏 |
| 可观测 | `/api/decision/cache`、`/system` | 字节利用率、命中率、淘汰/回收/拒写、最大 5 条目 |

### 6.5 兼容性与一致性约束

1. 新增字段一律追加，不改既有字段名与语义；旧前端忽略新字段仍可渲染。
2. 端点只新增不删改：原有 7 个决策端点保持不变，新增 `/scan`、`/bus`、`/cache`、`/system`、`/stream`。
3. 缓存公共接口签名不变，新增参数均有默认值。
4. 全 A 股口径优先；核心样本仅作降级并在 `data_scope / scope_label` 显式标注。
5. 缺失一律 `null + reason`，面板显示「--」并给原因，禁止补 0 或中性值。
6. 面板一致性：优先 `trace_id`，不同 trace 时按 180s 数据时点容差判「同窗口」，超出标「快照时差」。

### 6.6 本轮改动与影响范围

| 改动 | 原因 | 涉及模块 | 影响范围 | 验证 |
|---|---|---|---|---|
| 新增扫描层 | 只有广度与指数，缺横截面结构 | `market_scanner`、`decision-desk` | 决策台 14 → 17 卡 | 单测 3 项 + 双视口浏览器 |
| 板块轮动 | 只有当日强弱，无排名迁移 | `market_scanner`、E2、`sector_history` | 轮动信号/排名变化/动量窗口 | 两日合成数据单测 |
| 资金流向 | 资金面只有指数与北向代理 | `market_scanner`、E3 | 实测或显式代理 + 首日份额榜 | 真实接口 + 回退单测 |
| 专家团 v3 | 互评缺联合结论与命中追踪 | `decision_experts` | 联合研判 / 账本 / 否决复核 | 决策测试 27 项 |
| 数据总线 | 各模块自管 TTL，面板时点漂移 | `data_bus` + 各刷新点 | 依赖图 / 级联 / 事件推送 | `/bus` + 推流实测 |
| 缓存治理 | 只有条数上限，无法约束内存 | `cache.py` | 64MB 字节上限 / 拒写 / 统计 | 11 项总线缓存测试 |
| SSE 实时 | 固定轮询，最多 30s 延迟 | `routers/decision.py`、前端 | 实时推送 + 同快照标记 | `via=stream` 实测 |
